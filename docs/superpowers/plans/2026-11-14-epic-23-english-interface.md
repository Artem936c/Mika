# Эпик 23. Английский интерфейс

Дата: 2026-11-14.

## Цель

У Мики два языка интерфейса: русский и английский. Язык выбирается на экране первого запуска и на странице «Общие» и меняется без перезапуска: страницы, меню значка, ошибки команд и её собственные реплики из файла локализации идут за настройкой. При английском интерфейсе Мика отвечает на языке пользователя. Подробности и причины в решении 0035.

## Подход

Тексты обоих языков читает один модуль ядра `mika_core::i18n`: он вшивает `ru.json` и `en.json` и держит текущий язык процесса. `mika-gui::strings::tr` зовёт его, поэтому существующие вызовы не меняются. В интерфейсе текущий язык лежит в состоянии Svelte 5, а `t(key)` читает его при каждом вызове: шаблоны перерисовываются сами, вызовы `t` не правятся.

Эпик идёт параллельно с семью другими, поэтому новый код лежит в новых файлах, а в общих файлах правки в одну-три строки и не в конце списков. Тексты инструментов не переносятся: для них сделан механизм и одна строка ядра как проверка.

## Шаги

1. **Ядро: модуль `i18n`** (`mika-core/src/i18n.rs`, новый).
   - `Lang { Ru, En }`: код, разбор кода, язык по идентификатору языка Windows, имя по умолчанию.
   - Текущий язык процесса: `lang()`, `set_lang()`.
   - Тексты: `tr`, `tr_in`, `tr_args`, `tr_args_in`, `fill`. Порядок поиска: текущий язык, русский, сам ключ.
   - `I18nConfig { language }` и поле `Config::i18n`, раздел `[i18n]`.
   - `apply_defaults`: имя, имя для отклика и язык распознавания идут за языком, пока равны значению по умолчанию.
   - Язык голоса «Авто»: `set_speech_language`, `voice_language`, `voice_language_in`. Русский интерфейс — русский, английский — язык речи из настроек.
   - Тесты: одинаковые ключи и подстановки в двух файлах, нет кириллицы в `en.json`, нет пустых текстов, старый файл настроек без раздела, непонятное значение языка.
2. **Ядро: подсказки для английского режима** (`mika-core/src/i18n/prompt.rs`, новый).
   - Английская основа системной подсказки и четыре характера.
   - Строка-напоминание о языке ответа после подсказок инструментов.
   - `agent.rs`: `system_prompt` выбирает основу по языку, `full_system_prompt` добавляет напоминание.
3. **Ядро: ответы на вопрос о действии.**
   - `confirm.rs`: английские фразы согласия и отказа для чата, английские слова отказа для голоса. Одно слово «always» голосом не принимается: постоянное правило голосом требует фразы.
   - `session.rs`: строка «Сначала ответь на вопрос о действии…» берётся по ключу `core.answer_hint`.
4. **Язык Windows** (`mika-tools/src/win/locale.rs`, новый): `ui_language()` через `GetUserDefaultUILanguage`.
5. **Голос** (`mika-audio/src/win.rs`): в режиме «Авто» берётся голос языка, на котором она отвечает (`mika_core::i18n::voice_language`).
6. **Приложение** (`mika-gui`).
   - `lang.rs`, новый: первый запуск (`is_first_start`: нет ни настроек, ни базы), команды `get_language` и `set_language`, повторный выбор голоса `pick_voice`, английские подсказки пересказа и действий с выделенным текстом.
   - `strings.rs`: `tr` зовёт ядро.
   - `tray.rs`: пункты меню запоминаются, `retranslate` переписывает их и подсказку значка.
   - `app.rs`: язык ставится сразу после чтения настроек; новый профиль видит экран первого запуска и с ключом от прежней установки; подсказка пересказа выбирается по языку.
   - `selection.rs`, `settings.rs`, `main.rs`: по одной-две строки. В `settings.rs` голос выбирается заново при сохранении языка речи.
   - `mika-cli`: язык из настроек при старте.
7. **Интерфейс: язык и переключение** (`frontend`).
   - `locale.svelte.ts`, новый: таблицы, состояние языка, `setLang`, `lookup`, `nativeName`, `dateLocale`.
   - `i18n.ts`: `t` читает состояние; `MessageKey` и `isMessageKey` как были.
   - `main.ts`: язык спрашивается до отрисовки, смена приходит действием `language_changed`.
   - `LanguagePicker.svelte`, новый; строка в `General.svelte` и в `Welcome.svelte`. На экране первого запуска строка о русских карточках видна, пока выбран английский.
   - `ConfirmCard.svelte`, `confirm.ts`: строка над русским описанием при английском интерфейсе (`untranslated`).
   - Даты и время: `dateLocale()` в трёх местах.
8. **Перевод** (`frontend/src/locales/en.json`, новый): все ключи `ru.json` в том же порядке, по словарю и правилам из договора; шесть новых ключей в обоих файлах (`lang.*`, `core.answer_hint`, `confirm.untranslated`).
9. **Тесты интерфейса** (`i18n.test.ts`): одинаковые ключи в одном порядке, одинаковые подстановки, одинаковый набор ключей с вариантами через `|`, нет кириллицы в `en.json`, `t` идёт за языком. Тест «нет кириллицы вне файлов локализации» остаётся. Новый тест исходников: текст с подстановкой не запрашивается без значений (`t('ключ')` для текста с `{name}`).
10. **Предпросмотр** (`dev/mock.ts`): флаг `&lang=en`, команды `get_language` и `set_language`.
11. **Документы.** Решение 0035, дизайн §5, §8, §10, §12, строка в плане по эпикам.

### Запасной путь для шага 7

Если какой-то текст на странице не сменится при смене языка, состояние Svelte убирается, а окно при действии `language_changed` перезагружает страницу. Всё состояние вернётся из Rust, как при обычном старте; страница «Общие» открывается заново по отметке в `sessionStorage`. Вызовы `t` в компонентах не правятся и в этом случае.

Запасной путь не понадобился: в предпросмотре тексты меняются на месте (страница «Общие», открытый чат, экран первого запуска).

### После слияния восьми эпиков

Другие эпики добавляют ключи только в `ru.json`. После слияния отдельный шаг дописывает их в `en.json`:

1. `npm --prefix frontend test` — тест «en.json has the same keys as ru.json, in the same order» печатает недостающие и лишние ключи.
2. Каждый недостающий ключ вставляется в `en.json` на то же место, что в `ru.json`, и переводится по словарю из договора; подстановки `{…}`, варианты через `|`, разметка и пути сохраняются.
3. `npm --prefix frontend test`, `npm --prefix frontend run check`, `cargo test -p mika-core i18n` должны пройти.

## Проверка

`cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, `npm --prefix frontend test`, `npm --prefix frontend run check`, `npm --prefix frontend run build`.

Что ловит пропущенный ключ:
- `npm --prefix frontend run check`: `en.json` без ключа из `ru.json` — ошибка типа в `locale.svelte.ts`;
- `npm --prefix frontend test`: тест сравнения ключей в `i18n.test.ts`;
- `cargo test -p mika-core`: тест `locales_have_the_same_keys`.

Предпросмотр: `?mock=settings&page=general` (переключатель, смена языка на месте), `?mock=island&welcome&lang=en`, `?mock=chat&lang=en`, `?mock=confirm&lang=en`, `?view=avatar&mock=speak&lang=en`. Каждая страница настроек смотрится на английском: длинные надписи не должны ломать островок и карточки.

Тесты одного крейта язык процесса не переключают. Что модели при английском интерфейсе уходит английская основа и напоминание о языке после русских правил задач, а голос «Авто» идёт за языком речи, проверяет отдельная программа с одним тестом: `crates/mika-core/tests/english_interface.rs`.

Живой тест по умолчанию не запускается: `live_english_reply` — модель пользователя с английской основой и русскими подсказками отвечает по-английски на английский вопрос и по-русски на русский.

## Что не делаем

- Перенос русских текстов инструментов, карточки подтверждения и ошибок из кода Rust в файлы локализации: 1161 литерал, см. решение 0035.
- Перевод описаний инструментов и подсказок модели.
- Английский отклик на имя и английскую модель Vosk.
- Подтверждение высокого риска голосом по-английски.
- Перевод моста Telegram и отладочного клиента.
- Инструмент, которым модель меняла бы язык.
- Третий язык.
