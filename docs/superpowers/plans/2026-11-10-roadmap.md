# Мика: план реализации по эпикам

Дизайн: [docs/superpowers/specs/2026-11-10-mika-assistant-design.md](../specs/2026-11-10-mika-assistant-design.md).

Состояние на 2026-11-11: эпики 1–4 (веха В1, MVP) сделаны, см. [решение 0006](../../decisions/0006-mvp-scope.md). Выпущен пре-релиз 0.1.0-pre.1 с частью эпиков 6 и 11: установщик, значок, автозапуск, удаление данных ([решение 0007](../../decisions/0007-prerelease.md)). Пробная сборка 0.1 сделана, 0.2–0.5 впереди.

Этот документ задаёт порядок эпиков, их состав и условия готовности. Пошаговый план пишется отдельно для каждого эпика перед его началом, потому что решения ранних эпиков меняют детали поздних. Готовый пошаговый план есть для эпика 1: [2026-11-10-epic-01-foundation.md](2026-11-10-epic-01-foundation.md).

## Вехи

| Веха | Эпики | Что можно показать |
|---|---|---|
| В0. Ответы на вопросы | 0 | Записанные решения по окну, аватару, голосу, окнам Windows и лицензиям |
| В1. Текстовый помощник | 1–4 | В чате она отвечает, выполняет действия в Windows и спрашивает разрешение |
| В2. Голосовая колонка | 5–6 | Откликается на фразу, отвечает голосом, живёт в островке |
| В3. Живой персонаж | 7 | Аватар с эмоциями и движением губ, своя модель |
| В4. Полный контроль | 8–10 | Управляет любым окном, помнит, расширяется |
| В5. Выпуск | 11 | Установщик, автозапуск, обновления |

## Зависимости

```
0 ─► 1 ─► 2 ─► 3 ─► 4 ─► 5 ─► 6 ─► 7
                    │              └─► 11
                    ├─► 8
                    ├─► 9
                    └─► 10
```

Эпики 8, 9 и 10 не зависят друг от друга и могут идти параллельно после эпика 4.

## Эпик 0. Пробные сборки

**Цель.** Ответить на вопросы из раздела 13 дизайна до того, как на них будет опираться код.

Пробные сборки одноразовые: без тестов, без плана, без ревью. Код живёт в `spikes/` и не переносится в продукт. Результат каждой — файл решения в `docs/decisions/`.

**Состав**

- **0.1. Окно-островок.** Окно Tauri 2 без рамки, прозрачное, поверх всех окон, вверху по центру. Клики мимо островка проходят в окна под ним. Проверить два монитора с разным масштабом и смену размера с анимацией.
- **0.2. Аватар.** Отрисовка модели Live2D в окне Tauri. Движение губ по громкости звука. Загрузка модели из мастерской VTube Studio. Проверка упакованного формата Live2DViewerEX. Замер частоты кадров и нагрузки на процессор в покое.
- **0.3. Голосовой цикл.** Активационная фраза, определение конца речи, распознавание, потоковый ответ LLM, синтез по предложениям. Замер задержки каждого этапа на русском для двух-трёх локальных движков на этап.
- **0.4. Окна Windows.** Из Rust через UI Automation: найти окно Блокнота, ввести текст, нажать пункт меню. То же для одной программы на Electron. Записать, что недоступно.
- **0.5. Лицензии.** Условия Live2D Cubism SDK и выбранных голосовых моделей для личного и публичного использования.

**Готово, когда**

- В `docs/decisions/` лежат пять файлов: `0001-island-window.md`, `0002-avatar-engine.md`, `0003-voice-stack.md`, `0004-ui-automation.md`, `0005-licenses.md`.
- Каждый файл содержит: вопрос, что пробовали, замеры, решение, что это меняет в дизайне.
- Дизайн обновлён там, где решения его изменили.

**Риски.** Прозрачное окно с пропуском кликов может потребовать вызовов Win32 в обход Tauri. Формат Live2DViewerEX может оказаться закрытым.

## Эпик 1. Каркас

**Цель.** Рабочее пространство, в котором остальные эпики добавляют функции, а не инфраструктуру.

**Состав**

- **1.1.** Рабочее пространство Cargo и крейт `mika-core`.
- **1.2.** Шина событий и состояния помощника.
- **1.3.** Настройки в TOML.
- **1.4.** Хранилище секретов поверх Windows Credential Manager.
- **1.5.** Терминальный крейт `mika-cli`.
- **1.6.** Приложение `mika-gui`: окно-островок, мост событий, интерфейс на Svelte.
- **1.7.** Проверки в GitHub Actions.

**Готово, когда**

- `cargo test --workspace` проходит.
- `cargo run -p mika-cli` принимает строку и печатает смену состояний.
- `cargo tauri dev` показывает островок вверху экрана, который меняет форму при смене состояния.
- Ключ, сохранённый через приложение, виден в «Диспетчере учётных данных» Windows и не попадает в `config.toml`.

**Зависит от:** 0.1.

## Эпик 2. Текстовый чат и LLM

**Цель.** Она отвечает в чате через любого провайдера и умеет вызывать инструменты.

**Состав**

- **2.1.** Интерфейс провайдера LLM: сообщения, потоковый ответ, вызовы инструментов, отмена.
- **2.2.** Адаптер OpenAI-совместимого адреса.
- **2.3.** Адаптер Anthropic.
- **2.4.** Адаптер Ollama.
- **2.5.** Цикл агента: история, системный промпт, вызов инструмента, возврат результата, предел числа шагов.
- **2.6.** Реестр инструментов: имя, описание, схема аргументов, базовый риск. Два проверочных инструмента: текущее время и эхо.
- **2.7.** История разговоров в SQLite.
- **2.8.** Чат в интерфейсе: поток текста, строка выполненного действия со временем, кнопка остановки.
- **2.9.** Страница настроек «Провайдеры»: адрес, ключ, модель, кнопка «Проверить», измеренная задержка.

**Готово, когда**

- С тремя провайдерами проходит диалог из трёх реплик.
- Ответ появляется в чате по мере генерации.
- Вопрос «который час» приводит к вызову инструмента, и ответ содержит время.
- Смена провайдера в настройках действует без перезапуска.
- Обрыв сети посреди ответа показывает понятную ошибку, чат остаётся рабочим.

**Зависит от:** 1.

## Эпик 3. Политика рисков и подтверждения

**Цель.** Ни один инструмент не выполняется в обход проверки.

**Состав**

- **3.1.** Модель риска: три уровня, решение «выполнить, спросить, запретить».
- **3.2.** Хранилище правил: инструмент, шаблон аргументов, решение. Таблица в SQLite.
- **3.3.** Классификатор командной строки: разбор команды PowerShell и cmd, список опасных операций.
- **3.4.** Классификатор путей: системные папки, профиль пользователя, съёмные диски.
- **3.5.** Шлюз в цикле агента: каждый вызов инструмента идёт через политику. Обойти шлюз из кода инструмента нельзя по устройству типов.
- **3.6.** Карточка подтверждения в интерфейсе: кнопки, запрет «всегда» для высокого риска, отсчёт 60 секунд.
- **3.7.** Подтверждение сообщением в чате.
- **3.8.** Страница настроек «Разрешения»: список правил, отзыв.
- **3.9.** Журнал действий: что, когда, кем разрешено.

**Готово, когда**

- Вызов инструмента без правила показывает карточку.
- «Разрешать всегда» создаёт правило, повторный вызов проходит без вопроса.
- Для высокого риска правило создать нельзя ни кнопкой, ни фразой.
- Без ответа за 60 секунд действие отклоняется, LLM получает отказ.
- Тесты классификатора покрывают не меньше 40 команд, включая обфусцированные.

**Зависит от:** 2.

## Эпик 4. Инструменты, часть 1

**Цель.** Основные действия в Windows из текстового чата.

**Состав**

- **4.1. Система.** Громкость, яркость, сон, блокировка, перезагрузка, выключение, Wi-Fi, Bluetooth, буфер обмена, процессы, нагрузка.
- **4.2. Программы.** Запуск по имени, закрытие, переключение, список окон, раскладка по экрану.
- **4.3. Файлы.** Поиск, чтение, создание, перемещение, переименование, архивы, удаление в корзину.
- **4.4. Командная строка.** PowerShell и cmd с лимитом времени, перехватом вывода, отменой.
- **4.5. Интернет.** Поиск, чтение страницы, открытие ссылки в браузере.
- **4.6. Заметки.** Создание, поиск, чтение. Хранение в SQLite.
- **4.7. Удалёнка.** Список сохранённых RDP-подключений, открытие.
- **4.8. Погода.** Отдельный инструмент с карточкой в чате.

**Готово, когда**

- Сценарии из запроса пользователя проходят в чате: погода словами, погода в браузере, громкость, перезагрузка с подтверждением, удалёнка, файлы, заметки, команда в PowerShell.
- У каждого инструмента есть тест с подменой системного вызова.
- Долгая команда останавливается кнопкой.

**Зависит от:** 3.

## Эпик 5. Голос

**Цель.** Разговор голосом без заметной задержки от приложения.

**Состав**

- **5.1.** Захват микрофона, выбор устройства.
- **5.2.** Определение начала и конца речи.
- **5.3.** Активационная фраза, локально. Фраза задаётся в настройках.
- **5.4.** Интерфейс распознавания речи и адаптеры, выбранные в 0.3.
- **5.5.** Интерфейс синтеза речи и адаптеры, выбранные в 0.3. Потоковая озвучка по предложениям.
- **5.6.** Воспроизведение с очередью и мгновенной остановкой.
- **5.7.** Перебивание: речь пользователя останавливает озвучку.
- **5.8.** Голосовое подтверждение по правилам раздела 8 дизайна.
- **5.9.** Быстрые переключатели «Озвучка» и «Микрофон», страница настроек «Голос».
- **5.10.** Замер и показ задержки каждого этапа.

**Готово, когда**

- Фраза «Мика, какая погода» приводит к голосовому ответу.
- Собственная задержка каждого этапа укладывается в бюджет раздела 6 дизайна.
- Фраза «подтверждаю» из динамиков компьютера во время речи помощника не подтверждает действие.
- Высокий риск голосом подтверждается только повтором названия действия.
- Выключенный микрофон не захватывает звук: это проверяется по индикатору Windows.

**Зависит от:** 4, 0.3.

## Эпик 6. Островок

**Цель.** Интерфейс из макета.

**Состав**

- **6.1.** Шесть форм островка с пружинными переходами по таблице раздела 10 дизайна.
- **6.2.** Состояние «Отвечает»: текст по словам, выключатель озвучки.
- **6.3.** Развёрнутый чат: карточки инструментов, карточка погоды, поле ввода.
- **6.4.** Режимы окна: закреплён, островок на другом мониторе, обычное окно. Запоминание положения по мониторам.
- **6.5.** Поведение поверх полноэкранных программ: настройка «скрывать в играх».
- **6.6.** Окно настроек: каркас и страницы «Островок» и «Память».
- **6.7.** Значок в области уведомлений: показать, выключить микрофон, выйти.
- **6.8.** Тексты интерфейса в файлах локализации, русский язык.

**Готово, когда**

- Все состояния макета воспроизводятся в приложении.
- Переходы идут без рывков на мониторе 60 Гц.
- Открепление, перенос на второй монитор и режим окна работают и переживают перезапуск.
- Клики мимо островка попадают в окна под ним.

**Зависит от:** 5, 0.1.

## Эпик 7. Аватар и эмоции

**Цель.** Живой персонаж, которого можно заменить своей моделью.

**Состав**

- **7.1.** Отрисовка модели Live2D в островке.
- **7.2.** Базовые слои: дыхание, моргание, взгляд за курсором.
- **7.3.** Движение губ по звуку синтеза.
- **7.4.** Ядро эмоций в `mika-core`: десять слотов, сила, удержание, затухание, приоритеты.
- **7.5.** Метки эмоций в ответе LLM: правило в системном промпте, вырезание из текста, привязка к началу озвучки предложения.
- **7.6.** Эмоции от состояний и событий.
- **7.7.** Импорт модели: сканирование папки, автоматическое сопоставление по названиям, таблица ручной настройки с превью.
- **7.8.** Запасной вариант эмоций через стандартные параметры.
- **7.9.** Файл профиля модели.
- **7.10.** Отдельное окно аватара на рабочем столе с облачком речи.
- **7.11.** Страница настроек «Персонаж»: имя, модель, характер, сила движения губ, размещение.
- **7.12.** Встроенная модель по умолчанию. Откуда она берётся, решает пользователь: заказ у художника, покупка готовой с подходящей лицензией или свободная модель.

**Готово, когда**

- Встроенная модель показывает все десять эмоций.
- Губы двигаются в такт речи и останавливаются вместе с ней.
- Модель из мастерской VTube Studio загружается, моргает и говорит без настройки.
- Ручное сопоставление сохраняется и переживает перезапуск.
- Аватар в покое нагружает процессор не больше порога, записанного в решении 0002.

**Зависит от:** 6, 0.2, 0.5.

**Открытый вопрос к пользователю:** источник встроенной модели (7.12).

## Эпик 8. Управление окнами

**Цель.** Действия в любой программе.

**Состав**

- **8.1.** Инструмент чтения окна: дерево элементов в сжатом виде для LLM.
- **8.2.** Инструменты действия: нажать, ввести текст, выбрать пункт, прокрутить.
- **8.3.** Эмуляция клавиатуры и мыши.
- **8.4.** Зрение: снимок окна, запрос к модели с картинкой, клик по найденному месту.
- **8.5.** Разрешения по программам: вопрос при первом действии в новой программе.
- **8.6.** Показ цели перед кликом: подсветка элемента на экране.
- **8.7.** «Слепая зона» по заголовку окна.
- **8.8.** Переключатель «Экран» и инструмент «что на экране».
- **8.9.** Чтение текста с картинки.
- **8.10.** Сообщения об ограничениях: окна администратора, UAC.

**Готово, когда**

- «Открой Блокнот и напиши привет» выполняется.
- «Включи тёмную тему в параметрах Windows» выполняется.
- Первое действие в новой программе вызывает вопрос.
- Окно с заголовком «Вход в банк» не читается и не управляется.
- При выключенном переключателе «Экран» снимки не делаются.

**Зависит от:** 4, 0.4.

## Эпик 9. Быт и память

**Цель.** Возможности умной колонки и память о пользователе.

**Состав**

- **9.1.** Таймеры, будильники, напоминания с уведомлениями Windows и голосом.
- **9.2.** Список дел и календарь.
- **9.3.** Перевод, курсы валют, новости.
- **9.4.** Управление воспроизведением в любом плеере, «что играет».
- **9.5.** Долгая память: факты о пользователе, поиск по прошлым разговорам.
- **9.6.** Просмотр и удаление памяти на странице настроек «Память».
- **9.7.** Виджеты островка в состоянии покоя: погода, таймер, плеер.
- **9.8.** Характер: набор готовых и свой промпт.

**Готово, когда**

- «Напомни через десять минут выключить чайник» срабатывает голосом и уведомлением.
- Напоминание переживает перезапуск приложения.
- Факт, сказанный вчера, используется в ответе сегодня.
- Удалённый из памяти факт больше не используется.

**Зависит от:** 4.

## Эпик 10. Расширения

**Цель.** Возможности растут без изменения кода.

**Состав**

- **10.1.** Клиент MCP: подключение серверов, инструменты попадают в реестр и под политику.
- **10.2.** Свои команды: именованные наборы действий.
- **10.3.** Задачи по расписанию.
- **10.4.** Генерация картинок: интерфейс провайдера, адаптер, показ в чате.
- **10.5.** Управление браузером: вкладки, формы.
- **10.6.** Команды через Telegram с подтверждением там же.

**Готово, когда**

- Подключённый сервер MCP даёт инструменты, и они спрашивают разрешение.
- Команда «рабочий режим» открывает три заданные программы.
- Задача по расписанию выполняется при закрытом окне чата.
- Команда из Telegram от чужого аккаунта отклоняется.

**Зависит от:** 4.

## Эпик 11. Выпуск

**Цель.** Приложение ставится и обновляется без терминала.

**Состав**

- **11.1.** Установщик.
- **11.2.** Автозапуск с Windows, настройка.
- **11.3.** Первый запуск: выбор провайдеров, проверка микрофона, явное включение микрофона и экрана.
- **11.4.** Обновления: проверка, загрузка и установка только с подтверждением.
- **11.5.** Журналы и экран «Сообщить о проблеме» без отправки данных без согласия.
- **11.6.** Полное удаление данных из настроек.
- **11.7.** Подпись сборок. Решение о покупке сертификата за пользователем.

**Готово, когда**

- Чистая Windows 11: установка, первый запуск и первый голосовой ответ проходят без терминала.
- После установки микрофон и просмотр экрана выключены, пока пользователь их не включит.
- Удаление данных очищает `%APPDATA%\Mika`, `%LOCALAPPDATA%\Mika` и ключи в Credential Manager.

**Зависит от:** 7.

## Правила для всех эпиков

- Перед началом эпика пишется его пошаговый план в `docs/superpowers/plans/`.
- Каждый новый инструмент регистрируется в реестре с уровнем риска и проходит через политику. Исключений нет.
- Каждый инструмент имеет тест с подменой системного вызова.
- Микрофон, экран и сеть не используются без явного включения пользователем.
- Решения, меняющие дизайн, записываются в `docs/decisions/` и вносятся в дизайн.
