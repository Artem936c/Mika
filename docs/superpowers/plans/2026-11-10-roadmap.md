Эпик 21 «Глубокий поиск» ([решение 0033](../../decisions/0033-deep-search.md), план [2026-11-14-epic-21-deep-search.md](2026-11-14-epic-21-deep-search.md)): инструмент `deep_search` — запросы, поиск, чтение страниц, факты с источниками и отчёт Markdown со ссылками; лимиты поисков, страниц, минут и токенов; внутренние обращения к модели без инструментов; сетевой клиент только для открытого интернета.

Эпик 22 «Перенос на другой ПК» ([решение 0034](../../decisions/0034-backup-and-transfer.md), план [2026-11-14-epic-22-backup-and-transfer.md](2026-11-14-epic-22-backup-and-transfer.md)): копия в одном файле `.mikabackup` — настройки, переписка, память, заметки, дела, напоминания, свои команды, правила; с паролем файл зашифрован и несёт ключи, без пароля ключей в нём нет; восстановление с предпросмотром; разрешения «всегда» и задачи по расписанию только по отметке и только показанные в списке; микрофон, экран, Telegram и MCP после восстановления выключены, сеть и запуск программ копия не включает. Инструментов для модели нет.

Эпик 23 «Английский интерфейс» ([решение 0035](../../decisions/0035-english-interface.md), план [2026-11-14-epic-23-english-interface.md](2026-11-14-epic-23-english-interface.md)): язык интерфейса `ru` или `en` на экране первого запуска и на странице «Общие», смена без перезапуска; `en.json` со всеми ключами `ru.json`; тексты читает ядро, за языком идут страницы, меню значка, ошибки команд и её реплики; при английском интерфейсе Мика отвечает на языке пользователя. После слияния эпиков 16–23 переведены и 369 ключей остальных семи эпиков: в `ru.json` и `en.json` по 934 ключа (937 после проверки слитого дерева). Не сделано: русские литералы в коде Rust, которые видит пользователь (карточка подтверждения, ответы и ошибки инструментов): 1161 в самом эпике, 1639 после слияния — для переноса есть механизм. Итог дня, ответ на вопрос про экран и отчёт глубокого поиска при английском интерфейсе пока пишутся по-русски.

Сведение эпиков 16–23 в одно дерево: два решения пользователя поверх слитого. Достигнутый лимит расходов ставит на паузу платную работу, которую Мика начинает сама (сценарии по событию, задачи по расписанию, сводки, ответы в чатах), а просьбы пользователя не трогает ([решение 0028](../../decisions/0028-day-summary-and-costs.md)). Сценарии по событию вошли в копию для переноса своим разделом: показаны по одному, восстанавливаются выключенными и без счётчиков ([решение 0034](../../decisions/0034-backup-and-transfer.md), [решение 0031](../../decisions/0031-events-and-watching.md)). Новые выключатели эпиков 16–19 (диктовка, вопрос про экран, голосовые Telegram, вечерний итог) копия не включает.

Проверка слитого дерева тремя взглядами (само слияние; безопасность и деньги на стыках эпиков; документы, тексты и тесты) нашла и закрыла места, где эпики были верны по отдельности, но не вместе. Вопрос, заданный на компьютере (сценарий, задача по расписанию), из Telegram нельзя подтвердить, пока его карточка туда не пришла ([решение 0031](../../decisions/0031-events-and-watching.md), [решение 0029](../../decisions/0029-telegram-voice-and-mood-voice.md)). Итог фонового задания уходит в Telegram, только если задание начато оттуда; перезапуск после восстановления, установка обновления и «Удалить все данные» ждут конца процесса, который при выходе сохраняет запись ([решение 0032](../../decisions/0032-media-background-folders-recording.md)). Копия не снимает бюджет этого ПК; разрешение «всегда» покрывает только свою цель; текст своей команды показан под сценарием ([решение 0034](../../decisions/0034-backup-and-transfer.md)). Сводки и реплики о перерыве не принимают нажатия самой Мики за пользователя ([решение 0028](../../decisions/0028-day-summary-and-costs.md)). Карточка подтверждения в английском интерфейсе снова показывает цель записи экрана и сценария целиком ([решение 0035](../../decisions/0035-english-interface.md)).

Осталось, и всё ждёт решения пользователя: Live2D (7.1–7.3, 7.7–7.9) — принятие лицензии Cubism SDK и выбор модели (7.12); подпись сборок (11.7) — сертификат; сервер выпусков для обновлений.

Этот документ задаёт порядок эпиков, их состав и условия готовности. Пошаговый план пишется отдельно для каждого эпика перед его началом, потому что решения ранних эпиков меняют детали поздних. Готовый пошаговый план есть для эпика 1: [2026-11-10-epic-01-foundation.md](2026-11-10-epic-01-foundation.md).

## Эпик 0. Пробные сборки

**Цель.** Ответить на вопросы из раздела 13 дизайна до того, как на них будет опираться код.

Пробные сборки одноразовые: без тестов, без плана, без ревью. Код живёт в `spikes/` и не переносится в продукт. Результат каждой — файл решения в `docs/decisions/`.

**Состав**

- **0.1. Окно-островок.** Окно Tauri 2 без рамки, прозрачное, поверх всех окон, вверху по центру. Клики мимо островка проходят в окна под ним. Проверить два монитора с разным масштабом и смену размера с анимацией.
- **0.2. Аватар.** Отрисовка модели Live2D в окне Tauri. Движение губ по громкости звука. Загрузка модели из мастерской VTube Studio. Проверка упакованного формата Live2DViewerEX. Замер частоты кадров и нагрузки на процессор в покое.
- **0.3. Голосовой цикл.** Активационная фраза, определение конца речи, распознавание, потоковый ответ LLM, синтез по предложениям. Замер задержки каждого этапа на русском для двух-трёх локальных движков на этап.
- **0.4. Окна Windows.** Из Rust через UI Automation: найти окно Блокнота, ввести текст, нажать пункт меню. То же для одной программы на Electron. Записать, что недоступно.
- **0.5. Лицензии.** Условия Live2D Cubism SDK и выбранных голосовых моделей для личного и публичного использования.

**Готово, когда**

- В `docs/decisions/` лежат пять файлов: `0001-island-window.md`, `0002-avatar-engine.md`, `0003-voice-stack.md`, `0004-ui-automation.md`, `0005-licenses.md`.
- Каждый файл содержит: вопрос, что пробовали, замеры, решение, что это меняет в дизайне.
- Дизайн обновлён там, где решения его изменили.

**Риски.** Прозрачное окно с пропуском кликов может потребовать вызовов Win32 в обход Tauri. Формат Live2DViewerEX может оказаться закрытым.

## Эпик 2. Текстовый чат и LLM

**Цель.** Она отвечает в чате через любого провайдера и умеет вызывать инструменты.

**Состав**

- **2.1.** Интерфейс провайдера LLM: сообщения, потоковый ответ, вызовы инструментов, отмена.
- **2.2.** Адаптер OpenAI-совместимого адреса.
- **2.3.** Адаптер Anthropic.
- **2.4.** Адаптер Ollama.
- **2.5.** Цикл агента: история, системный промпт, вызов инструмента, возврат результата, предел числа шагов.
- **2.6.** Реестр инструментов: имя, описание, схема аргументов, базовый риск. Два проверочных инструмента: текущее время и эхо.
- **2.7.** История разговоров в SQLite.
- **2.8.** Чат в интерфейсе: поток текста, строка выполненного действия со временем, кнопка остановки.
- **2.9.** Страница настроек «Провайдеры»: адрес, ключ, модель, кнопка «Проверить», измеренная задержка.

**Готово, когда**

- С тремя провайдерами проходит диалог из трёх реплик.
- Ответ появляется в чате по мере генерации.
- Вопрос «который час» приводит к вызову инструмента, и ответ содержит время.
- Смена провайдера в настройках действует без перезапуска.
- Обрыв сети посреди ответа показывает понятную ошибку, чат остаётся рабочим.

**Зависит от:** 1.

## Эпик 3. Политика рисков и подтверждения

**Цель.** Ни один инструмент не выполняется в обход проверки.

**Состав**

- **3.1.** Модель риска: три уровня, решение «выполнить, спросить, запретить».
- **3.2.** Хранилище правил: инструмент, шаблон аргументов, решение. Таблица в SQLite.
- **3.3.** Классификатор командной строки: разбор команды PowerShell и cmd, список опасных операций.
- **3.4.** Классификатор путей: системные папки, профиль пользователя, съёмные диски.
- **3.5.** Шлюз в цикле агента: каждый вызов инструмента идёт через политику. Обойти шлюз из кода инструмента нельзя по устройству типов.
- **3.6.** Карточка подтверждения в интерфейсе: кнопки, запрет «всегда» для высокого риска, отсчёт 60 секунд.
- **3.7.** Подтверждение сообщением в чате.
- **3.8.** Страница настроек «Разрешения»: список правил, отзыв.
- **3.9.** Журнал действий: что, когда, кем разрешено.

**Готово, когда**

- Вызов инструмента без правила показывает карточку.
- «Разрешать всегда» создаёт правило, повторный вызов проходит без вопроса.
- Для высокого риска правило создать нельзя ни кнопкой, ни фразой.
- Без ответа за 60 секунд действие отклоняется, LLM получает отказ.
- Тесты классификатора покрывают не меньше 40 команд, включая обфусцированные.

**Зависит от:** 2.

## Правила для всех эпиков

- Перед началом эпика пишется его пошаговый план в `docs/superpowers/plans/`.
- Каждый новый инструмент регистрируется в реестре с уровнем риска и проходит через политику. Исключений нет.
- Каждый инструмент имеет тест с подменой системного вызова.
- Микрофон, экран и сеть не используются без явного включения пользователем.
- Решения, меняющие дизайн, записываются в `docs/decisions/` и вносятся в дизайн.
