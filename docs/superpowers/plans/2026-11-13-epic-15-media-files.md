# Эпик 15. Видео и аудио файлы

Дата: 2026-11-13.

## Цель

Мика меняет формат видео и звука, сжимает, режет, склеивает, делает GIF, поворачивает, ускоряет, обрабатывает звук, вшивает субтитры, распознаёт речь в файле и рассказывает, что в видео. Всё это делает FFmpeg: свой у пользователя или скачанный по кнопке. Подробности и правила в решении 0027.

## Подход

Инструменты живут в `mika-tools`, в новом модуле `ffmpeg` и группе `av`. Каждый инструмент проверяет пути политикой файлов, сам собирает аргументы FFmpeg и запускает его через `Runner` без оболочки. Результат пишется во временное имя и переименовывается в конце. Ход работы идёт в чат новым событием `ToolProgress`. Распознавание и зрение идут через трейты ядра, которые уже есть у микрофона и экрана. Скачивание FFmpeg — дело приложения, по образцу Vosk: кнопка, ход, проверка SHA-256.

Работа делится на две части, которые идут параллельно: ядро и инструменты, приложение и интерфейс. Общие имена и поля закреплены заранее.

## Шаги

1. **Ядро** (`mika-core`).
   - `ToolsConfig::ffmpeg_path`, по умолчанию пусто.
   - `paths::ffmpeg_dir()`: `%LOCALAPPDATA%\Mika\ffmpeg`, с учётом `MIKA_DATA_DIR`.
   - `Event::ToolProgress { id, share }`.
   - `tools::progress_handle()` и `Progress::set(share)`: ход инструмента, который знает свой вызов. Агент оборачивает `run` в область вызова.
   - `ToolError::NotReady { message, data }`: ошибка, у которой есть карточка для чата. Агент отдаёт её данные в `ToolFinished` и при ошибке `assess`, и при ошибке `run`.
   - `SpeechSegment` и `SpeechToText::transcribe_segments`, по умолчанию `Ok(None)`.
   - `Vision::ask_frames`, по умолчанию первый кадр через `ask`.
2. **Провайдеры** (`mika-providers`).
   - `transcribe_segments`: `response_format=verbose_json`, `timestamp_granularities[]=segment`, разбор `segments`. Нет фраз или отказ формата — `Ok(None)`.
   - `ask_frames`: все кадры в одном сообщении, подсказка про кадры видео.
3. **Запуск процессов** (`mika-tools`).
   - `Runner::run_streaming`: рабочая папка и строки stdout по мере вывода. По умолчанию — обычный `run`, строки после конца.
   - `Runner::run_blocking`: короткий запуск без асинхронности, для `ffprobe` в `assess`.
   - `ProcessRunner` реализует оба, с `kill_on_drop` и снятием дерева процессов.
   - Подделки в `testing.rs`: запись рабочей папки, ответы, распознавание речи.
4. **Модуль `ffmpeg`** (`mika-tools/src/ffmpeg.rs` и папка `ffmpeg/`).
   - `locate`: поиск по настройке, PATH и папке Мики; `version` для страницы настроек.
   - `probe`: разбор JSON ffprobe, кэш по пути, размеру и времени изменения, отказ для плейлистов, проверка файла субтитров перед вшиванием.
   - `time`: разбор времени `90`, `1:30`, `01:02:03.5`.
   - `output`: имена результатов, временное имя, страж удаления.
   - `encoders`: список кодировщиков, пробное кодирование, выбор H.264, флаги качества и битрейта.
   - `progress`: разбор `-progress pipe:1`.
   - `args`: чистые функции, которые собирают аргументы каждой операции; у каждого входа `-format_whitelist` и `-protocol_whitelist file`.
   - `job`: запуск с ходом, сроком и «Стоп», переименование результата.
   - `wav`: нарезка WAV и разбор `silencedetect`, `loudnorm`.
   - `srt`: запись субтитров.
5. **Инструменты** (`mika-tools/src/ffmpeg/*.rs`). Двенадцать инструментов из решения 0027, с оценкой риска, проверкой аргументов в `assess` и карточкой результата `av_files`. Область «всегда» — пара папок: входы и результат.
6. **Реестр** (`mika-tools/src/lib.rs`).
   - Группа `av` в `GROUPS` и блок `if on("av")`.
   - Строки `HINTS` для группы.
   - Счётчики в тестах реестра.
   - Поля `Shared`: `ffmpeg_path`, `stt`, `av_outputs`.
7. **Приложение: связка** (`mika-gui/src/app.rs`, `mika-cli`, `win.rs`). Поля `Shared` и `Ctx` заполняются; `stt` — тот же `live`, что у микрофона.
8. **Приложение: скачивание** (`mika-gui/src/ffmpeg_get.rs`). По образцу `vosk.rs`: закреплённый адрес, размер и сумма, проверка переадресации, распаковка трёх файлов, удаление.
9. **Приложение: команды** (`settings.rs`, `main.rs`). `get_ffmpeg_status`, `set_ffmpeg_path`, `install_ffmpeg` с событием `ffmpeg-progress`, `remove_ffmpeg`, `open_av_file`.
10. **Интерфейс** (`frontend`).
    - Блок FFmpeg на странице «Инструменты» перед группами.
    - Карточка `ffmpeg_missing` с согласием и кнопкой «Скачать».
    - Карточка `av_files` с кнопками «Открыть» и «Показать в папке».
    - Проценты в строке инструмента по событию `tool_progress`.
    - Ключи в `ru.json`, сценарии в `dev/mock.ts`.
11. **Документы.** Решение 0027, дизайн §5, §7, §10, §11, строка в плане по эпикам.

## Проверка

`cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, `npm --prefix frontend test`, `npm --prefix frontend run check`, `npm --prefix frontend run build`.

Каждый инструмент проверяется тестом с подделанным `Runner`: какие аргументы ушли FFmpeg, какое имя получил результат, какой уровень риска. Сборщики аргументов проверяются отдельно, без процессов.

Живые тесты по умолчанию не запускаются:
- `live_ffmpeg_ops`: если FFmpeg найден, каждая операция на коротком файле, который делает сам FFmpeg из `lavfi`;
- `live_ffmpeg_download`: скачивание закреплённой сборки и проверка суммы;
- `live_transcribe_segments`: отдаёт ли провайдер пользователя время фраз.

## Что не делаем

- Фоновые задания и очередь: ход ждёт FFmpeg, «Стоп» его прерывает.
- Обрезку тишины в видео.
- Обработку папок одним вызовом.
- Локальное распознавание и `arnndn`.
- Запись экрана, потоки и скачивание видео из интернета.
- Скачивание FFmpeg из чата без кнопки и из Telegram.
