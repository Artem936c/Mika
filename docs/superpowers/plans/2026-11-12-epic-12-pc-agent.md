# Эпик 12. Агент для ПК

**Цель.** Мика выполняет задачи в несколько шагов:

1. составляет план;
2. выполняет шаги;
3. проверяет каждый шаг;
4. показывает ход в чате;
5. останавливается по кнопке «Стоп».

К этому добавлены управление браузером и пакетные действия с файлами. Каждый новый инструмент идёт через политику рисков, слепая зона действует и в браузере.

**Архитектура.**

- Ядро (`mika-core`) хранит доску задачи и поднимает лимит шагов, пока у задачи есть план.
- Инструменты браузера и пакета файлов живут в `mika-tools`. Браузер спрятан за интерфейсом `Browser`, чтобы инструменты проверялись без настоящего браузера.
- Svelte только рисует ход задачи по событию `task_updated`.

## Что уже есть

- Цикл агента: не больше 8 запросов к модели на одно сообщение.
- Остановка: `Session::stop` и кнопка «Стоп» в чате.
- Окна: чтение и управление через UI Automation. Экран: снимок, текст с экрана, описание.
- Файлы: найти, прочитать, записать, переместить, создать папку, удалить в корзину.
- Сайт открывается только в браузере пользователя. Управлять страницей нельзя.

## Шаги

### 12.1 Доска задачи и длинные задачи

- `mika-core/src/task.rs`:
  - `TaskBoard` — общая доска текущей задачи: название и шаги со статусами `pending`, `active`, `done`, `failed`, `skipped`.
  - Инструменты `task_plan` и `task_step`. Оба низкого риска: меняют только доску.
- Событие `Event::TaskUpdated`: название, шаги с заметками, `finished`, `ok`.
- Агент очищает доску в начале сообщения. Пока у задачи есть план, лимит шагов `TASK_MAX_STEPS = 40` вместо 8.
- Конец сообщения закрывает задачу. Незавершённые шаги становятся «пропущен», после остановки активный шаг — «не вышло: остановлено».
- В системной подсказке правила задачи:
  - план для задачи больше чем из трёх действий;
  - проверка после каждого действия;
  - после двух неудач подряд — вопрос пользователю.
- Тесты: задача из 12 шагов проходит дальше прежнего лимита; без плана лимит прежний; остановка помечает шаг.

### 12.2 Браузер

- Отдельный профиль Edge (или Chrome) в папке данных: `<данные>\browser`. Запуск с `--remote-debugging-port` на свободном порту `127.0.0.1`. Профиль пользователя не трогается. Порт открыт только на этом компьютере.
- Протокол отладки (CDP) через WebSocket: `tokio-tungstenite` без TLS.
- Инструменты, группа `browser`:
  - `browser_open` — открыть адрес; низкий риск, нужен переключатель «Интернет»;
  - `browser_read` — адрес, заголовок, текст и пронумерованные элементы страницы; низкий;
  - `browser_click` — нажать элемент по номеру; средний;
  - `browser_type` — ввести текст в поле, `submit` нажимает Enter; средний;
  - `browser_scroll` — прокрутить; низкий.
- Разрешение «всегда» привязано к сайту.
- Слепая зона:
  - страница с полем пароля;
  - адрес или заголовок с признаками входа, банка или оплаты (`is_blind_url` рядом с `is_blind_title`).

  Такие страницы не читаются и не управляются.
- Тесты: разбор снимка страницы, слепая зона по адресу и по полю пароля, уровни риска, поддельный `Browser`.

### 12.3 Пакет файлов

- `list_folder`: содержимое папки с размером, датой и типом, фильтр по расширению, до 300 строк. Низкий риск.
- `file_batch`: до 200 действий `move`, `copy`, `rename`, `mkdir`, `trash` одним подтверждением.
  - Карточка подтверждения показывает число действий каждого вида и первые 15 строк.
  - Уровень — наибольший из уровней путей. С `trash` — высокий.
  - Занятое имя получает суффикс « (2)». Отчёт по каждому действию.
- Тесты на временной папке: перенос, копирование, конфликт имён, отказ при отсутствии источника, уровни.

### 12.4 Ход задачи в интерфейсе

- `chat.ts`: `reduceTask` по `task_updated`.
- `TaskPanel.svelte` над полем ввода:
  - название и «3 из 7»;
  - шаги со значками;
  - активный шаг подсвечен;
  - кнопка «Стоп», пока задача идёт.
- Тексты в `ru.json`, сценарий предпросмотра `?mock=task`.

### 12.5 Подсказки и проверка

- Подсказки инструментов (`HINTS`) для браузера, пакета файлов и плана.
- Проверка вживую на дешёвой модели RouterAI:
  - задача в браузере: найти и прочитать;
  - разбор тестовой папки пакетом;
  - остановка посреди задачи.
- Решение `docs/decisions/0014-pc-agent.md`, изменения в дизайне, сборка и установка.

## Правила

- Действия высокого риска нельзя разрешить навсегда.
- Слепая зона проверяется в инструменте до любого действия.
- Браузер пользователя и его профиль не трогаются. Вход на сайты в профиле Мики пользователь делает сам: страницы входа — слепая зона.
