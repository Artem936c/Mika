# Эпик 21. Глубокий поиск

Дата: 2026-11-14.

## Цель

Мика отвечает на сложный вопрос в несколько шагов: составляет поисковые запросы, ищет, читает страницы, выписывает факты с источниками и сохраняет отчёт Markdown со ссылками. В чат она возвращает короткий вывод, путь к файлу и карточку. Работа ограничена числом поисков, страниц, минутами и токенами, идёт внутри хода и прерывается кнопкой «Стоп». Подробности и правила в решении 0033.

## Подход

Один инструмент `deep_search` в группе `web`, в новом модуле `research` крейта `mika-tools`. Шаги ведёт код: модель внутри только отвечает текстом, инструментов у неё нет. Разбор выдачи и снятие разметки берутся из `web.rs`. Сеть идёт через свой клиент с проверкой адресов: старый `Http::get` защиты не даёт. Текстовая модель приходит в инструменты так же, как зрение и распознавание: трейт `TextModel` в ядре, реализация у `Live`, поле в `Shared`. Ход работы идёт событием `ToolProgress` из эпика 15, новых событий нет. Карточка отчёта открывает файл той же командой `open_av_file`, что и файлы видео и звука.

Правки общих файлов малы и только добавляют строки; новый код лежит в новых файлах.

## Шаги

1. **Ядро** (`mika-core`).
   - `config.rs`: раздел `ResearchConfig` (`folder`, `model`, четыре лимита), `ResearchLimits` с границами, `Config::research`.
   - `llm.rs`: трейт `TextModel` (`model_id`, `complete`) и функция `complete_capped`: один запрос без инструментов, вызовы инструментов отбрасываются, размышления вырезаются, чтение обрывается на пределе знаков ответа и на пределе всего присланного вместе с размышлениями (`stream_cap`). Ответ `TextAnswer` и ошибка `TextFailure` несут число присланных знаков.
2. **Провайдеры** (`mika-providers`). Новый файл `text.rs`: `impl TextModel for Live`. Модель из аргумента, пусто — модель для ответов; адрес и ключ — как у LLM. В `live.rs` — доступ к хранилищу секретов для этого файла. В `common.rs` задача, читающая поток ответа, кончается сразу, как только ответ перестали читать.
3. **Сеть** (`mika-tools/src/research/net.rs`).
   - `check_url`: схема, имя и пароль, порт, имя узла, адрес цифрами, «слепая зона».
   - `is_public_ip`: открытый ли это адрес.
   - `PublicResolver`: DNS, который отдаёт клиенту только открытые адреса.
   - `GuardedHttp`: клиент без прокси и кук, с этой DNS, проверкой каждой переадресации, пределом размера и срока; кодировки UTF-8 и Windows-1251.
   - Трейт `Net`, чтобы тесты подставляли сеть.
4. **Разбор и чистка** (`mika-tools/src/research/`).
   - `page.rs`: заголовок, главный блок страницы, текст, границы для недоверенного текста.
   - `plan.rs`: подсказка плана и разбор запросов.
   - `sources.rs`: приведение адресов, отбор страниц по очереди из запросов, не больше двух с сайта.
   - `extract.rs`: подсказка фактов, разбор и чистка фактов.
   - `write.rs`: подсказка отчёта, чистка текста модели, номера источников, пометка «без источника», короткий вывод, отчёт без модели.
   - `report.rs`: сборка файла, имя, проверка папки до работы, запись только новым файлом.
   - `budget.rs`: оценка токенов, остаток, запас под ответ с размышлениями, сроки.
5. **Конвейер и инструмент** (`research/run.rs`, `research.rs`). Порядок шагов, до трёх страниц одновременно, лимиты, ход в процентах, «Стоп»; одна страница под двумя адресами читается один раз; вывод возвращается и тогда, когда файл не записался. `DeepSearchTool`: описание, проверка аргументов и риск в `assess`, запуск. Запись запусков `ResearchRuns`: правило «всегда» покрывает не больше одного поиска за раз, одного в 10 минут и пяти в сутки, а запуск идёт только под той карточкой, по которой его разрешили.
6. **Реестр** (`mika-tools/src/lib.rs`, `sys.rs`, `web.rs`, `testing.rs`). Модуль `research`, регистрация в группе `web`, строка в `HINTS`, счётчик в тесте. Поля `Shared`: `text_model`, `research` и `research_runs`. `web::search_url` — общий адрес поиска. Подделка `TextModel` и `Net` для тестов.
7. **Связка** (`mika-gui/src/app.rs`, `mika-cli/src/main.rs`). Три поля `Shared`.
8. **Приложение: команды** (новый `mika-gui/src/research.rs`, строки в `main.rs`). `get_research_settings`, `set_research_settings`.
9. **Интерфейс** (`frontend`).
   - Карточка `research_report` (`ResearchCard.svelte`), разбор в `chat.ts`, строка в `Chat.svelte`.
   - Блок «Глубокий поиск» на странице «Инструменты» (`settings/Research.svelte`, чистые функции в `research.ts`).
   - Ключи `research.*` в `ru.json`, сценарии `research` и `research_ask` в `dev/mock.ts`.
10. **Документы.** Решение 0033, дизайн §5, §7, §10, §11, строка в плане по эпикам.

## Проверка

`cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, `npm --prefix frontend test`, `npm --prefix frontend run check`, `npm --prefix frontend run build`.

Что проверяют тесты:
- сеть: отказ для `file:`, `ftp:`, имени с паролем, чужого порта, `localhost`, имени без точки, `127.0.0.1` во всех записях, частных и служебных адресов IPv4 и IPv6, страниц входа и оплаты; отказ на шестой переадресации и на переадресации на частный адрес; `PublicResolver` отклоняет `localhost`; `GuardedHttp` не соединяется с `127.0.0.1`;
- конвейер с подделанными сетью и моделью: адреса берутся только из выдачи; ссылка из текста страницы не открывается; каждый внутренний запрос идёт без инструментов; текст страницы стоит внутри границ; число поисков, страниц и обращений к модели не больше лимитов; при исчерпанных токенах или времени отчёт пишется неполным и это названо; при ошибке модели на шаге отчёта пишется отчёт без неё;
- чистка: ссылки, картинки, HTML и голые адреса убраны из текста модели; ссылка внутри ссылки, экранированные скобки, адрес без `http` и определение ссылки внутри цитаты или списка ссылкой не становятся; чужие номера источников убраны; абзац без номера помечен; список источников собран из данных кода; заголовок «Источники тепла» не обрезает отчёт;
- расход: размышления в ответе входят в счёт и обрывают чтение на пределе; потраченное не выходит за лимит токенов; наибольший лимит страниц при наименьшем лимите токенов всё равно читает страницы;
- инструмент: средний риск; высокий при лимите токенов больше 100 тысяч и при папке в Program Files; высокий сразу после поиска, во время другого поиска и после пяти поисков за сутки; запуск отклоняется, если настройки изменились после карточки; область «всегда» меняется вместе с лимитами; отказ при выключенном интернете до карточки; негодная папка кончает поиск до платных шагов; «Стоп» не оставляет файла;
- провайдеры: брошенный запрос закрывает соединение, пока модель присылает одни размышления;
- интерфейс: разбор карточки, аргументы команды настроек.

Живые тесты по умолчанию не запускаются:
- `live_guarded_fetch`: настоящая страница читается, выдача DuckDuckGo разбирается;
- `live_deep_search`: весь поиск с моделью пользователя и малыми лимитами.

Глазами: сценарии `?mock=research` и `?mock=research_ask`, страница `?mock=settings&page=tools`.

## Что не делаем

- Фоновую работу: это эпик фоновых заданий.
- Подписи этапов в строке инструмента и новые события.
- Точный счёт токенов и правки `LlmRequest`.
- Второй круг поиска, чтение PDF, страниц на скриптах и страниц за входом.
- Повтор обращений к модели после ошибки.
- Работу через прокси.
- Защиту старых `fetch_page` и `web_search` от локальных адресов.
- Неполный отчёт после «Стоп».
