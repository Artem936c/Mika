# Мика: живой ИИ-помощник для Windows. Дизайн

Дата: 2026-11-10. Статус: черновик на утверждение.
Макет интерфейса: [docs/design/island-mockup.html](../../design/island-mockup.html) (открыть в браузере, все состояния кликабельны).

«Мика» — рабочее имя персонажа и проекта. Его можно сменить без переделки архитектуры: имя персонажа хранится в настройках, имена крейтов меняются одной заменой.

## 1. Замысел

Локальный голосовой и текстовый помощник для Windows с живым 2D-персонажем. По возможностям это умная колонка плюс полный доступ к компьютеру: всё, что можно сделать в чате с ИИ-агентом, можно сделать через неё голосом или текстом.

Зачем: готовые решения закрывают задачу по частям. У Yuna есть живой персонаж и агент, но модель работает на чужих серверах. У Priler/jarvis есть быстрый офлайн-стек на Rust, но нет LLM и понимания смысла. У NabyScape есть удобный островок, но агентная часть вынесена наружу. Проект объединяет эти идеи в одном приложении, где пользователь сам выбирает провайдеров.

## 2. Цели, не-цели, анти-цели

### Цели

1. Помощник откликается на активационную фразу и на текст в чате.
2. Он выполняет действия в Windows: система, программы, файлы, командная строка, окна любых программ.
3. Каждое действие проходит проверку риска. Подтвердить можно кнопкой, сообщением в чате или голосом.
4. Разрешение даётся на один раз или навсегда.
5. Любой LLM-провайдер подключается через настройки. Провайдеры распознавания речи, синтеза речи и картинок тоже сменные.
6. Приложение не добавляет заметной задержки: скорость ответа упирается только в провайдеров.
7. Интерфейс — островок вверху экрана с анимациями, чатом и быстрым выключателем озвучки. Окно открепляется, переносится на другой монитор и превращается в обычное окно.
8. Персонаж — аватар в аниме-стиле с эмоциями и движением губ во время речи. Модель сменная: пользователь подключает свою модель VRM, в том числе взятую из Steam. Модели Live2D отложены (решение 0039).

### Не-цели первой версии

- Другие операционные системы, кроме Windows 10 (сборка 19041 и новее) и Windows 11.
- Мобильное приложение. Удалённые команды с телефона идут через Telegram (эпик 10).
- Собственные серверы, учётные записи, подписки.
- Обучение собственных моделей.
- 3D-аватар.

### Анти-цели

Проект провален, даже если технически работает, когда:

- помощник выполнил опасное действие без подтверждения;
- случайная фраза из видео или фильма подтвердила действие;
- ключи провайдеров лежат в открытом файле;
- микрофон или экран слушаются и смотрятся без явного включения пользователем;
- приложение само добавляет к ответу сотни миллисекунд.

## 3. Ограничения

- Платформа: Windows 10 19041+ и Windows 11, x64.
- Стек: Rust (редакция 2021), Tauri 2, Svelte и Vite для интерфейса.
- Данные, память и настройки хранятся локально. В сеть уходят только запросы к выбранным провайдерам и инструментам.
- Ключи хранятся в Windows Credential Manager.
- Журнал приложения хранится только на этом компьютере и никуда не отправляется. Ключи и содержимое окон «слепой зоны» в него не попадают никогда, тексты разговоров — только после явного включения (решение 0036).
- Код Priler/jarvis не копируется. В README проекта указана лицензия CC BY-NC-SA 4.0, в его `Cargo.toml` указана GPL-3.0-only. Обе накладывают условия на производный код. Из проекта берутся только идеи и стиль организации кода (см. раздел 12).
- Модель аватара рисуется в интерфейсе через three.js и `@pixiv/three-vrm`, обе под MIT. Live2D отложен: его SDK требует отдельного договора для программ, в которые пользователь загружает произвольные модели, и это решается до выпуска с Live2D (решение 0039).
- Модели из мастерской Steam принадлежат авторам. Приложение их не распространяет, пользователь подключает свои локально.

## 4. Кто что решил

### Решения пользователя

- Стек Rust и Tauri.
- Активационная фраза, голос и текст.
- Проверка риска для всех действий, разрешение на один раз или навсегда, три способа подтверждения.
- Любой LLM-провайдер.
- Островок вверху экрана, чат в нём, быстрый выключатель озвучки, три режима окна.
- 2D-аватар в аниме-стиле с эмоциями и движением губ, поддержка готовых моделей из Steam.
- Аватар может жить и в островке, и отдельно на рабочем столе.
- Управление любым окном Windows.
- Каталог возможностей из раздела 7.
- Стиль кода берётся у Priler/jarvis.
- Копия для переноса на другой ПК хранит и ключи, но только зашифрованными паролем пользователя (решение 0034).
- Журнал самой Мики: что она делала, что не получилось и почему (решение 0036).

### Мои решения (пользователь их видел и не оспорил, но явно не утверждал)

- Опасные действия нельзя разрешить навсегда.
- Голосовое подтверждение опасного действия требует повторить его название, а не сказать «да».
- При первом действии в каждой новой программе помощник спрашивает разрешение.
- Удаление файлов идёт в корзину. Удаление мимо корзины требует отдельного подтверждения.
- Движок аватара общий: встроенные картинки, модель VRM, позже Live2D. VRM сделан первым, потому что формат открытый (решение 0039).
- Десять слотов эмоций (раздел 9).
- Бюджет собственной задержки (раздел 6).
- Разбиение на крейты (раздел 5).
- Чистка секретов в журнале не выключается; тексты разговоров и аргументы инструментов пишутся в журнал только по явному включению и по умолчанию выключены; инструмент чтения журнала для модели — низкий риск (решение 0036).

## 5. Архитектура

### Крейты

Раскладка повторяет подход Priler/jarvis: рабочее пространство Cargo, общее ядро, отдельные исполняемые крейты.

| Крейт | Назначение | Зависит от |
|---|---|---|
| `mika-core` | Шина событий, состояние, настройки, хранилище секретов, цикл агента, политика рисков, ядро эмоций, память, журнал приложения (решение 0036). Без зависимостей от Windows и Tauri. | — |
| `mika-providers` | Адаптеры LLM, эмбеддингов, зрения, картинок, клиент MCP, мост Telegram. Только HTTP и дочерние процессы. | `mika-core` |
| `mika-audio` | Озвучка ответов голосом Windows или готовым звуком от провайдера, запись фразы с микрофона, определение конца речи (решения 0009, 0010), активационная фраза на Vosk или распознавателе Windows (решения 0012, 0020). | `mika-core` |
| `mika-tools` | Инструменты Windows: система, файлы, командная строка, окна, веб. | `mika-core` |
| `mika-cli` | Текстовый чат в терминале для отладки ядра без интерфейса. | все библиотечные |
| `mika-gui` | Приложение Tauri 2: окна, команды, мост событий к интерфейсу. | все библиотечные |

Интерфейс на Svelte лежит в `frontend/`. Он только рисует состояние и отправляет команды. Вся логика живёт в Rust.

### Поток данных

1. Вход: активационная фраза и речь (`mika-audio`) или текст из чата (`mika-gui`).
2. Распознавание превращает речь в текст (`mika-providers`).
3. Цикл агента (`mika-core`) отправляет историю и список инструментов в LLM и получает поток ответа.
4. Если LLM вызывает инструмент, вызов уходит в политику рисков. Политика разрешает, спрашивает пользователя или запрещает.
5. Разрешённый инструмент выполняется (`mika-tools`), результат возвращается в LLM.
6. Текст ответа идёт потоком в чат и по предложениям в синтез речи.
7. Ядро эмоций получает состояние и метки из ответа и управляет аватаром.

Все части общаются через шину событий. Интерфейс подписан на шину через мост Tauri.

### Состояния помощника

`Idle` (ждёт), `Listening` (слушает), `Thinking` (думает), `Speaking` (отвечает), `AwaitingConfirm` (ждёт подтверждения). Островок, аватар и звук реагируют на смену состояния.

### Хранение

- Настройки: `%APPDATA%\Mika\config.toml`. Язык интерфейса — раздел `[i18n]`, поле `language`: `ru` или `en` (решение 0035).
- Ключи: Windows Credential Manager, служба `Mika`.
- История, архив прошлых разговоров, факты памяти и их векторы, заметки, напоминания, список дел, свои команды, правила разрешений: SQLite в `%APPDATA%\Mika\mika.db`.
- Картинки и снимки экрана: `Изображения\Mika` и `Изображения\Screenshots` в профиле пользователя.
- Отчёты глубокого поиска: `Документы\Mika\Research` в профиле пользователя; папку можно сменить в настройках (решение 0033).
- Модели аватара, их профили эмоций и портреты: `%LOCALAPPDATA%\Mika\models\<id>\`. Папка привязана к компьютеру, в копию для переноса не входит; «Удалить все данные» стирает и её (решение 0039).
- Скачанный по кнопке FFmpeg: `%LOCALAPPDATA%\Mika\ffmpeg\` (`ffmpeg.exe`, `ffprobe.exe`, `LICENSE.txt`) (решение 0027).
- Расходы на провайдеров и журнал дня: в той же `mika.db`. Расходы — по дням и моделям, только числа, имя модели и имя сервера, 400 дней. Журнал дня — сессии фокуса, сделанные дела, сработавшие напоминания, законченные задачи, 60 дней (решение 0028).
- Сценарии по событию: таблица `triggers` в `mika.db` и таблица их запусков `trigger_runs` (по ней считаются пределы; записи старше двух суток удаляются). Слежения «подожди и скажи» живут только в памяти и после перезапуска не продолжаются (решение 0031).
- Записи экрана: `Видео\Mika` в профиле пользователя. Пока запись идёт, её куски лежат рядом в папке `<имя записи>.mika-part`; куски, оборванные окном из «слепой зоны», в ней не остаются (решение 0032).
- Журнал приложения: `%LOCALAPPDATA%\Mika\logs\`. Текущий файл `mika.log`, прежние `mika.1.log` … `mika.N.log`, метка идущего запуска `mika.running`. Поворот при 5 МБ; настройки — раздел `[log]` в `config.toml` (решение 0036).
- Копия прежних данных перед восстановлением: `%APPDATA%\Mika\backups\before-restore.mikabackup`, без ключей (решение 0034).

### Копия и перенос

Пользователь сохраняет всё своё в один файл `.mikabackup` и восстанавливает его на другом ПК (решение 0034). В копию входят настройки, переписка и архив, факты памяти, заметки, дела, напоминания, задачи по расписанию, свои команды, сценарии по событию и правила разрешений. Не входят журналы, кэш фраз, векторы, указатель документов, FFmpeg, модель Vosk, профиль браузера Мики, учёт расходов, журнал дня, счёт запусков сценариев и слежения «подожди и скажи».

С паролем файл шифруется целиком (PBKDF2-HMAC-SHA256, AES-256-GCM) и несёт ключи из Credential Manager. Без пароля файл не зашифрован, и ключей в нём нет. Пароль не хранится.

Восстановление показывает предпросмотр и ничего не меняет до подтверждения. Отмеченный раздел заменяет данные этого ПК; прежние данные перед этим сохраняются. Запреты только добавляются: запреты этого ПК восстановление не удаляет. Всё, что слушает, смотрит, следит, запускает программы или принимает команды со стороны, восстанавливается выключенным: микрофон, просмотр экрана, чтение уведомлений, время в программах, история буфера, мост Telegram, серверы MCP, папки документов. Так же выключенными приходят диктовка в любое окно, вопрос про экран и голосовые сообщения моста Telegram. Интернет-инструменты, календарь, утренняя сводка, вечерний итог и общий выключатель сценариев остаются включёнными, только если включены и на этом ПК. Паузу платной работы при достигнутом лимите расходов копия не выключает: пока на этом ПК учёт включён, пауза включена и задан лимит, учёт, лимиты, валюта и свои цены остаются от этого ПК. Вид и место окна, путь к FFmpeg, папка отчётов глубокого поиска и адрес обновлений остаются от этого ПК. Настройки журнала переносятся, но запись текстов и аргументов (`log.content`) после восстановления всегда выключена, и итог называет её среди выключенного (решение 0036). Из копии приходит только то, что было показано: восстанавливается тот самый файл, который прошёл предпросмотр (сверка по SHA-256).

Сценарии по событию — свой раздел копии. В предпросмотре каждый показан строкой: событие, программа или устройство, действие, пауза и предел в день. Восстанавливаются они выключенными и без счётчиков; пауза и счёт дня берутся из запусков, которые этот ПК помнит для того же имени. Пределы решения 0031 проверяются при чтении: известное событие, поручение до 300 знаков одной строкой, пауза и предел в своих границах, не больше 30 сценариев; негодная строка отбрасывается и считается. Сценарий, который запускает свою команду, восстанавливается, только если после восстановления эта команда есть на ПК: восстановлена из копии или уже была.

### Журнал

Журнал отвечает на вопрос «что Мика делала, что не получилось и почему» (решение 0036). Его пишет свой приёмник в ядре, `mika_core::journal`: код зовёт макросы `log`, приёмник чистит сообщение, пишет строку в файл и держит последние 2000 записей в памяти. `mika-cli` пользуется тем же приёмником без файлов: записи идут в stderr, уровень задаёт переменная `MIKA_LOG`.

- **Строка.** Одна запись — одна строка, четыре поля через табуляцию: время (RFC 3339 с миллисекундами и местным смещением), уровень (`ERROR`, `WARN`, `INFO`, `DEBUG`), категория, сообщение. Табуляция, перевод строки и обратная косая черта в сообщении экранируются. Сообщение не длиннее 2000 знаков. Записи пишутся по-английски.
- **Файлы.** Поворот при 5 МБ. Прежних файлов хранится не больше `keep_files` (по умолчанию 5) и не дольше `keep_days` (14); срок действует на прежние файлы, текущий живёт до поворота. Старые `mika.old.log` и `mika.log` прежнего `env_logger` удаляются при первом запуске. Поворот не заменяет существующий файл: если прежний файл держит другая программа, поворот откладывается. Удалённый во время работы текущий файл создаётся заново. Записи, не дошедшие до диска, читаются из памяти.
- **Категории.** `app`, `turn`, `llm`, `tool`, `policy`, `voice`, `telegram`, `mcp`, `events`, `jobs`, `costs`, `backup`, `update`, `hotkeys`, `web`, `lib`. Категория — цель записи: `log::info!(target: "tool", …)`. Запись без цели получает категорию по пути модуля. Записи чужих крейтов идут в `lib` и только с уровня `WARN`.
- **Настройки** `[log]`: `level` (`error`, `warn`, `info`, `debug`; по умолчанию `info`), `content` (`false`), `keep_days`, `keep_files`. Применяются сразу, без перезапуска; смена, которую не удалось сохранить, не применяется. Раздел читается терпимо: непонятное значение заменяется значением по умолчанию своего поля и не роняет остальные настройки.
- **Чистка секретов** стоит в приёмнике и не выключается. Значение каждого секрета запоминается, когда его читают из хранилища ключей, и заменяется на `***`. Кроме значений чистятся виды: `Bearer …`, `Authorization: …`, ключи вида `sk-…`, токен бота Telegram, пары `api_key=`, `token=`, `password=`, `secret=` и подобные, имя и пароль в адресе. Всё, что читается из файлов назад, чистится ещё раз.
- **Содержимое.** Пока `log.content` выключен, в журнал не пишутся: текст пользователя и модели, продиктованный и распознанный текст, заголовки окон, буфер обмена, содержимое файлов, значения аргументов инструментов, поисковые запросы, строка запроса в адресах, текст сообщений Telegram, факты памяти. Не пишется и текст ошибки инструмента, сервера MCP и фонового задания: он цитирует заголовки окон, пути и аргументы; пишется только вид ошибки. Пишутся имена, уровни риска, решения, длительности, размеры, коды ответа и тексты ошибок самого приложения, системы и провайдера до 300 знаков. От жалобы FFmpeg остаётся причина без пути. С включённым `log.content` добавляются начало сообщения пользователя и ответа, аргументы инструментов и тексты их ошибок, до 500 знаков на запись; продиктованный текст не пишется никогда. Текст сокращается после чистки секретов.
- **«Слепая зона»** не пишется ни в каком режиме: ни заголовок, ни содержимое, ни набранный текст. Вызов, который отклонила сама «слепая зона», записывается с исходом `blind_zone`, без текста ошибки и с пометкой `<blind zone>` на месте аргументов. Текст, в котором только встретилось слово-признак, скрывается другой пометкой, которая не утверждает, что такое окно было.
- **Что записывается.** Запуск и выход, сохранение настроек; начало и конец каждого хода с его номером; одна запись на запрос к провайдеру (модель, длительность, токены, код ответа, повторы) и ничего на кусок потока; начало и конец каждого вызова инструмента (имя, риск, решение, длительность, исход); записи одного хода несут его номер `turn=N`, запуск FFmpeg из задания — номер задания; вопросы политики и ответы на них; распознавание, синтез и микрофон; мост Telegram; серверы MCP; сценарии и слежения; фоновые задания и каждый запуск FFmpeg; предупреждения бюджета; копия и восстановление; обновления; сочетания клавиш; глубокий поиск. В горячих циклах записей нет. Отказ, который повторяется, пишется в первый раз, затем редко, и один раз — когда работа вернулась.
- **Паника** оставляет запись `ERROR` категории `app` с местом и сообщением, файл сбрасывается на диск. При выключенных текстах от сообщения остаются первые слова: паника может цитировать текст, на котором случилась.
- **Незавершённый запуск.** Метка `mika.running` создаётся при запуске и удаляется при чистом выходе; конец сеанса Windows считается чистым выходом. Если метка осталась, в журнале появляется `WARN`, а в чате — одна спокойная строка со ссылкой на журнал.
- **Сторож.** Тест каждого крейта читает вызовы макросов `log` и не пропускает переменную с именем содержимого без помощника `journal::content`, `guarded`, `guarded_error`, `complaint` или `address`, раскрытие секрета и печать целых настроек, запроса или ответа.

Журнал решений о действиях (`audit` в `mika.db`) — другая вещь: в нём решения политики, он остаётся как был.

## 6. Скорость

Мой бюджет собственной задержки приложения, без учёта провайдеров:

- от активационной фразы до начала записи: до 200 мс;
- от конца речи до отправки звука в распознавание: до 50 мс;
- от первого фрагмента ответа LLM до его появления в чате: до 30 мс;
- от конца первого предложения ответа до отправки в синтез: до 30 мс;
- от получения первого звука синтеза до воспроизведения: до 50 мс.

Приёмы: потоковый ответ LLM, озвучка по предложениям без ожидания конца ответа, перебивание голосом, постоянные соединения с провайдерами, локальная активационная фраза.

При синтезе у провайдера запрос на каждое предложение уходит сразу, как оно готово, а играют они по порядку: задержка провайдера приходится только на первую фразу (решение 0010). Замеренная у RouterAI задержка: синтез фразы 1,5–2,0 с, распознавание 0,9–2,2 с. Это задержка провайдера, а не приложения. Каждый этап пишет в журнал время, его видно в чате под ответом: распознавание, первое слово модели, первый звук (решение 0011).

## 7. Возможности

Каждая возможность — это инструмент, который LLM вызывает по имени. Уровень риска по умолчанию указан в скобках.

- **Окна и программы.** Запуск, закрытие, переключение, раскладка по экрану и перенос на другой монитор (низкий) (решение 0025). В Telegram сообщение, картинка или файл отправляются по готовому рецепту: файл вставляется через буфер обмена, без нажатий по скрепке (высокий риск, решение 0025). Клики и ввод в любой программе (средний, при первом действии в новой программе спрашивает).
- **Система.** Громкость, громкость отдельной программы, яркость (низкий). Wi-Fi, Bluetooth, буфер обмена, процессы, нагрузка и температура (низкий для чтения, средний для изменений). «Почему тормозит»: замер, тяжёлые программы, диски, батарея и выводы (низкий). Сон, блокировка (средний). Перезагрузка, выключение, завершение процессов (высокий) (решение 0024).
- **Файлы.** Поиск по имени и по тексту внутри файлов, что занимает место, открытие, чтение, содержимое папки (низкий). Создание, перемещение, переименование, архивы (средний). Удаление в корзину (высокий). Удаление мимо корзины (высокий, отдельное подтверждение). Пакет до 200 действий одним подтверждением; карточка показывает список, уровень — наибольший из путей (решение 0014).
- **Командная строка.** PowerShell и cmd. Команды чтения (средний). Команды, меняющие систему (высокий). Скрипты из интернета (высокий).
- **Интернет.** Поиск, чтение страниц, открытие ссылок (низкий). Браузер Мики в своём профиле Edge: открыть и прочитать страницу (низкий), нажать и ввести текст (средний, «всегда» — для одного сайта) (решение 0014). Поиск, чтение страниц и погода выключены, пока пользователь не включит интернет-инструменты в настройках; открытие ссылки в браузере работает всегда (решение 0006).
- **Глубокий поиск.** Ответ на сложный вопрос в несколько шагов: Мика составляет поисковые запросы, ищет, читает страницы, выписывает факты с источниками и сохраняет отчёт Markdown со ссылками; в чат идут короткий вывод и карточка отчёта (средний: это несколько платных обращений к модели и новый файл; высокий, если лимит токенов больше 100 тысяч или поиски идут один за другим). Правило «всегда» покрывает не больше одного поиска за раз, одного в 10 минут и пяти в сутки: об остальных Мика спрашивает. Шаги ведёт код, а не модель. Внутренние обращения к модели идут без инструментов, текст страниц для неё — данные, а не указания. Адреса берутся только из выдачи поиска: только `http` и `https`, только открытый интернет, без локальных и частных адресов и без переадресаций на них; страницы входа, банков и оплаты не читаются. Жёсткие лимиты на один поиск: поисков, страниц, минут и токенов; карточка подтверждения их называет, и поиск идёт только под той карточкой, по которой его разрешили. Токены считаются приблизительно; рассуждения, которые модель пишет в ответе, входят в счёт. В тексте отчёта ссылок нет: они есть только в списке источников, который пишет код. Место без источника в отчёте помечено. «Стоп» прерывает поиск на любом шаге и не оставляет файла. Работает при включённых интернет-инструментах (решение 0033).
- **Быт.** Погода, таймеры, будильники, напоминания, заметки, список дел, календарь, перевод, курсы валют, новости (низкий). Утренняя сводка раз в день после заданного времени, когда пользователь за компьютером (выключена по умолчанию) (решение 0024).
- **Уведомления.** Мика читает новые уведомления Windows из базы уведомлений, только чтение, пока пользователь не выключит. Включаются отдельным переключателем. Уведомления банков, кодов и паролей не читаются. Уведомление попадает в разговор и по желанию звучит вслух. По просьбе Мика следит за перепиской с человеком в Telegram и на каждое его сообщение предлагает ответ; отправка всегда с подтверждения (решение 0024).
- **Ритм дня.** Режим фокуса на время: уведомления копятся, после фокуса Мика перечисляет пришедшее. Напоминание о перерыве после долгой работы без паузы (выключено по умолчанию). Учёт времени в программах по имени процесса, только на этом компьютере, 60 дней (выключен по умолчанию). История последних 50 скопированных текстов, только в памяти; пароли, ключи, коды, помеченные программами паролей копии и копии из окон «слепой зоны» не попадают (выключена по умолчанию). Все инструменты чтения — низкий риск (решение 0025).
- **Итог дня.** Вечерняя половина сводки: после заданного времени, раз в день, на тех же условиях, что утренняя (выключена по умолчанию). Код собирает факты дня из базы: время в программах, если его учёт включён, фокус, встречи, сделанные дела, напоминания, задачи Мики, расходы. Текст пишет один короткий запрос к модели без инструментов; без ответа модели итог составляет код. Названия встреч и дел в фактах — данные: одна строка до 120 знаков; ответ модели не длиннее 600 знаков. В конце Мика предлагает план на завтра. По просьбе те же факты отдаёт инструмент `day_summary` (низкий) (решение 0028).
- **Календарь.** Встречи по секретной ссылке ICS из Google, Outlook или Яндекса; ссылка — секрет в Credential Manager. Повторы, исключения, переносы и часовые пояса разбираются. Напоминание за N минут, встречи в утренней сводке (низкий) (решение 0025).
- **Документы.** Вопросы по документам из выбранных папок: txt, md, csv, html, docx, pdf (pdf распознаётся по страницам средствами Windows). Куски текста с векторами модели эмбеддингов, без неё поиск по словам. Ответ называет файл и страницу (низкий) (решение 0025).
- **Выделенный текст.** Сочетание Ctrl+Alt+X копирует выделение из любой программы. Карточка в чате предлагает перевести, исправить, перефразировать, сократить или объяснить; ответ можно вставить на место выделенного кнопкой. Окна из «слепой зоны» не трогаются (решение 0024).
- **Диктовка в любое окно.** Сочетание Ctrl+Alt+D: пользователь говорит, и распознанный текст печатается там, где стоит курсор, без модели и без Enter. Короткое нажатие — запись кончается по паузе, удержание — пока клавишу не отпустят; не дольше 45 секунд. Выключена, пока пользователь её не включит, и требует включённого «Микрофона». В окнах из «слепой зоны», в поле пароля, в поле, которое не удалось проверить, и в окне Мики не записывает и не печатает; окно проверяется до записи, до отправки звука и перед печатью. Пока Мика отвечает, диктовка ждёт (решение 0030).
- **Вопрос про экран.** Сочетание Ctrl+Alt+Q снимает только окно, которое впереди; в чате появляется карточка со снимком и полем вопроса, по умолчанию «объясни, что на экране». Снимок и вопрос уходят модели со зрением по кнопке «Спросить» или голосом, ответ приходит в чат. Выключен, пока пользователь его не включит, и требует включённого «Экрана». Окно из «слепой зоны» не снимается; снимок на диск не пишется. Снимок делается и вопрос уходит только пока Мика свободна; в историю разговора идёт название программы, а не заголовок окна (решение 0030).
- **Медиа.** Пауза, следующий трек, «что играет» в любом плеере (низкий).
- **Видео и звук.** Файлы через FFmpeg: сведения о файле (низкий); смена формата, звук из видео, сжатие до размера или качества, меньшее разрешение, кусок по времени, склейка, GIF, поворот, скорость, выравнивание громкости, обрезка тишины, шумоподавление, громкость, вшивание субтитров (средний: пишется новый файл рядом, исходник не меняется, занятое имя не перезаписывается). Речь из файла в текст и `.srt` через провайдера распознавания (средний, больше 10 минут звука — высокий: это платно). «Что в видео» по кадрам через модель зрения (средний). Только файлы этого компьютера и распространённые форматы: скрипты и плейлисты не открываются; без оболочки и сетевых протоколов. «Всегда» действует для пары папок: откуда читается и куда пишется. «Стоп» завершает FFmpeg и удаляет недоделанный файл (решение 0027).
- **Видео и звук: фон, папки, запись.** Долгая работа FFmpeg (перекодирование от 3 минут, распознавание от 10 минут или параметр `background`) после обычного подтверждения уходит в фоновое задание: Мика сразу отвечает, чат показывает карточку с ходом и кнопкой «Стоп», об окончании она говорит своей репликой. Одно задание работает, остальные ждут в очереди; при выходе задания останавливаются, недоделанные файлы удаляются. Перезапуск после восстановления копии, установка обновления и удаление всех данных ждут, пока этот выход закончится. Задание работает только с теми файлами, которые были при подтверждении: изменённый или подменённый за время ожидания файл не обрабатывается. Целая папка обрабатывается одним вызовом и одной карточкой: смена формата, сжатие, обработка звука, речь в текст; не больше 100 файлов, риск наибольший по файлам, распознавание больше 10 минут в сумме — высокий. Карточка закрепляет список файлов: если папка изменилась, пока карточка ждала, ничего не запускается; распознавание папки нельзя разрешить навсегда. Запись экрана или окна со звуком компьютера, по просьбе с микрофоном: начало всегда высокий риск и требует включённого «Экрана» (для микрофона — «Микрофона»), предел 30 минут, не больше 120; результат в `Видео\Mika`. FFmpeg записи завершается вместе с приложением, как бы оно ни закрылось (решение 0032).
- **Экран.** Описание экрана, чтение текста с картинки, нажатие по надписи или по картинке, скриншот (средний, просмотр экрана выключен по умолчанию).
- **Общение.** Анекдоты, словесные игры, разговор, память о пользователе (без риска, инструмент не нужен).
- **Генерация.** Картинки и текстовые документы (низкий).
- **Удалёнка.** Открытие сохранённых RDP-подключений (средний).
- **Свои команды.** Именованные наборы действий и задачи по расписанию (риск равен самому опасному действию в наборе).
- **События и наблюдение.** Сценарий по событию: подключили или отключили звуковое устройство, запустили или закрыли программу, подключились по RDP или отключились, заблокировали или разблокировали компьютер, пользователь отошёл или вернулся — Мика выполняет свою команду или поручение. У сценария есть выключатель, пауза между запусками и предел в день, на все сценарии — предел в час; пределы хранятся в базе, и их не обнуляют ни перезапуск, ни удаление сценария. Создание сценария — средний риск. Нажатия самой Мики не считаются ни возвращением пользователя, ни его присутствием: утренняя сводка, вечерний итог и реплики о перерыве спрашивают время простоя у того же датчика. «Подожди и скажи»: файл появился или перестал расти, процесс завершился, в окне появилась или пропала фраза (низкий, только чтение; средний для папок Windows, сетевых папок и папок других пользователей); срок до 8 часов, не больше пяти слежений сразу. Итог приходит в чат, голосом, уведомлением Windows и в Telegram. Наблюдается только свой сеанс Windows, заголовки окон сценарии не сравнивают, окна «слепой зоны» не читаются, модель в наблюдении не участвует (решение 0031).
- **Расширения.** Внешние инструменты через MCP (средний, пока пользователь не назначил иначе). Сервер запускается как программа или доступен по адресу HTTP (решение 0011).
- **Телефон.** Команды через Telegram (те же уровни риска, подтверждение приходит в Telegram). Вопрос хода, начатого на компьютере (сценарий, задача по расписанию, просьба в чате), в Telegram сам не уходит, и сообщение оттуда на него не отвечает, пока владелец не получил его карточку: первое сообщение показывает карточку, следующее или кнопка отвечают (решение 0031). Итог фонового задания приходит в Telegram, только если задание начато оттуда (решение 0032).
- **Расходы.** Каждый платный вызов провайдера считается: токены ответов и зрения, знаки озвучки, секунды распознавания, картинки, эмбеддинги. Деньги — только когда цена известна: из ответа провайдера, из его списка моделей или введённая пользователем; иначе показываются единицы. Бюджет на день и на месяц предупреждает на 80% и 100%. Просьбы пользователя он не блокирует никогда: чат, голос, клавиши, кнопки, сообщения владельца из Telegram и вызванные ими инструменты работают и после 100%. На 100% Мика ставит на паузу только платную работу, которую начинает сама: запуски сценариев по событию, задачи по расписанию, утреннюю сводку и вечерний итог, ответы в чатах, за которыми она следит. Пропущенный запуск сценария в его счёт не идёт. Паузу выключает настройка `costs.pause_unattended` (включена по умолчанию). О паузе Мика говорит один раз за период, строкой в чате. Предупреждения и строка о паузе вслух не звучат; во время фокуса ждут его конца отдельно от уведомлений. «Сколько потрачено» отвечает инструмент `cost_report` (низкий) (решение 0028).
- **Журнал приложения.** На вопрос «почему не сработало?» Мика читает собственный журнал инструментом `journal_read` (низкий, только чтение): записи не ниже заданного уровня (по умолчанию предупреждения и ошибки) за последние минуты (60, не больше суток), по желанию одной категории и с заданным текстом; в ответе не больше 100 записей. Это журнал самого приложения, а не журналы Windows и не другие программы. Записи в ответе помечены как данные, а не указания. Ответ уходит провайдеру модели, как ответ любого инструмента: ключей в журнале нет, а тексты разговоров в нём есть только за то время, пока пользователь включал их запись; предупреждение перед включением говорит об этом (решение 0036).
- **Голосовые в Telegram.** Голосовое сообщение владельца до 2 минут распознаёт та же модель, что и голос с микрофона. Бот показывает распознанный текст и выполняет его как текстовую команду: тот же аккаунт, те же уровни риска и кнопки. Пересланное голосовое и голосовое старше 5 минут не выполняются; длина проверяется по самому файлу, а не по словам отправителя. Остановка в Telegram или на компьютере отменяет и голосовые, которые ещё распознаются или ждут очереди. На голосовое Мика может ответить голосовым: голос провайдера, не больше 500 знаков слов и 250 знаков разметки, остальное в тексте. Оба переключателя выключены по умолчанию (решение 0029).
- **Задачи в несколько шагов.** Модель составляет план и отмечает шаги; чат показывает ход и кнопку «Стоп». С планом допустимо до 40 запросов к модели, без плана 14 (решение 0022), а о незакрытых шагах ядро напоминает ей до двух раз (решение 0014). Так же ядро напоминает, если модель молча закончила ход после инструментов или пообещала действие («подожди секунду») вместо вызова инструмента (решение 0021).

Инструменты объединены в группы. Группу можно выключить на странице «Инструменты», и тогда модель её не видит (решение 0009). Встроенных инструментов 109; последний добавленный — `journal_read` в группе «Система» (решение 0036).

Три возможности запускает сам пользователь сочетанием клавиш, без модели: выделенный текст, диктовку и вопрос про экран. Это не инструменты, модель и Telegram вызвать их не могут. Сочетание диктовки и вопроса про экран зарегистрировано в Windows, только пока включены действие и «Микрофон» или «Экран» (решение 0030).

### Память

Факты о пользователе хранятся в базе и подставляются в системный промпт. С моделью эмбеддингов поиск по фактам и прошлым разговорам идёт по смыслу; без неё — по словам. «Новый разговор» не стирает чат, а убирает его в архив, по которому помощник ищет. Архив и факты стираются на странице «Память» (решение 0009).

### Управление окнами: три уровня

1. **Windows UI Automation.** Помощник видит дерево элементов окна и действует по имени элемента. Нажимать можно по номеру или подписи, несколько кнопок — одной цепочкой. После каждого действия инструмент перечитывает окно и сообщает, что изменилось, закрылось ли окно и не появился ли диалог (решение 0017). Программы из Microsoft Store запускаются по списку приложений Windows, уже открытая программа выводится вперёд. Сообщение в мессенджер отправляется с очисткой поля и не уходит дважды (в других программах поле не очищается); текст со смайликами вставляется через буфер обмена. Переписку программ, которые рисуют её сами (Telegram, Discord), Мика читает `screen_text` (решение 0022). Сообщение человеку в Telegram отправляет отдельный инструмент `messenger_send`: поиск по всем чатам, проверка заголовка открытого чата распознаванием до отправки, без проверки — только после «да» пользователя (решение 0023).
   Окно выводится вперёд несколькими способами по очереди, и после каждого Мика проверяет, что впереди действительно оно: одного запроса мало, когда команда пришла голосом и сама Мика не впереди. Настройки Windows при этом не меняются. `focus_window` открывает вкладку браузера по названию (`tab`), а название, которого нет среди окон, ищет среди вкладок открытых браузеров; `list_windows` с `tabs` перечисляет вкладки. Вкладки читаются только при включённой группе «Управление окнами» (решение 0038).
2. **Эмуляция клавиатуры и мыши.** Для элементов без имён.
3. **Зрение.** `screen_click` сначала ищет надпись распознаванием текста на этом компьютере и нажимает в её середину. Если надписи нет, снимок с пронумерованной сеткой уходит в модель со зрением: она называет клетку, затем клетку внутри неё (решение 0024). Перед нажатием модель видит перекрестие на точке и подтверждает её. Если не подтвердила, вторая попытка — точка в пикселях; без подтверждения нажатия нет. Снимок для клика берётся с экрана, а снимок и клик считают в физических пикселях (решение 0025). Окна Мики в снимок не попадают, чужие окна поверх цели закрашиваются, а остров на время клика пропускает его в этом месте (решение 0025). Для игр и нестандартных интерфейсов.

Ограничения, о которых помощник честно сообщает: окна с правами администратора недоступны, пока приложение не запущено от администратора; запрос UAC автоматизировать нельзя; окна с паролями, банками и оплатой помощник не смотрит и не трогает.

## 8. Политика рисков

### Уровни

- **Низкий.** Действие ничего не ломает и легко отменяется.
- **Средний.** Действие меняет данные или настройки, но отменяется.
- **Высокий.** Действие нельзя отменить или оно затрагивает работу всей системы.

### Как принимается решение

1. Инструмент сообщает базовый уровень риска.
2. Классификатор уточняет его по аргументам: путь, команда, программа. Для командной строки он разбирает команду и ищет опасные операции.
3. Политика ищет сохранённое правило для пары «инструмент и шаблон аргументов».
4. Итог: выполнить, спросить или запретить.

Пока действует решение пользователя «проверять всё»: без сохранённого правила помощник спрашивает даже для низкого риска. Правило «разрешать всегда» создаётся кнопкой в карточке или фразой в чате. Оно действует только на ту цель, для которой дано: запрет — шаблон со звёздочкой, а разрешение сравнивается с целью вызова целиком, и правило `*` покрывает только инструменты без своей цели. Правило `*`, пришедшее из копии для инструмента, который называет свою цель (папка на распознавание, сценарий), ничего не разрешает (решение 0034). У вызовов с вкладками браузера своя цель постоянного правила (`tab` у `focus_window`, `tabs` у `list_windows`): прежнее «разрешать всегда» для переключения окон на них не действует, о вкладках Мика спросит заново (решение 0038).

Сценарий по событию не получает поблажек: его вызовы инструментов проходят ту же политику, что и просьба из чата, а карточка подтверждения ждёт пользователя те же 60 секунд. Создание сценария спрашивается для каждого нового сценария: правило «всегда» охватывает только тот же самый сценарий с тем же именем. Карточка сценария показывает его целиком, без прокрутки: пределы, событие и всё поручение или текст команды. Сценарий запоминает отметку текста команды и не запускается, если команду с тех пор изменили (решение 0031).

Сохранение копии и восстановление из неё — не инструменты: модель, команда из Telegram и сервер MCP запустить их не могут. То же с журналом: модель может только читать его инструментом `journal_read`, а очистка, сохранение в файл и настройки журнала доступны только на странице «Журнал» (решение 0036). Правила «разрешать всегда» и задачи по расписанию из копии восстанавливаются только по отдельной отметке в предпросмотре и только те, что там показаны; запреты из копии добавляются к запретам этого ПК. Сценарии по событию из копии восстанавливаются только показанные и только выключенными: сценарий начинает действовать после того, как пользователь включил его на этом ПК, и выполняет только тот текст своей команды, который был подтверждён при его создании; этот текст показан под сценарием на странице «Расширения» (решение 0034).

### Подтверждение

Карточка показывает: что будет сделано простыми словами, точную команду или цель клика, почему присвоен такой риск, кнопки «Разрешить один раз», «Разрешать всегда», «Отклонить».

- Кнопкой: в островке или в чате.
- В чате: «да», «разреши всегда», «отмена». По-английски: «yes», «always allow», «no»; засчитывается только фраза целиком (решение 0035).
- Голосом для низкого и среднего риска: «подтверждаю» или «отмена». По-английски согласие на один раз принимается теми же целыми фразами, что в чате; постоянное правило — только фразой «always allow», «allow always» или «yes always» (одно слово «always» работает лишь в чате); слово отказа («no», «not», «don't», «wait», «stop», «cancel») в любом месте фразы отклоняет действие. Высокий риск голосом по-английски не подтверждается, пока название действия на карточке русское: остаётся кнопка (решение 0035).
- Голосом для высокого риска: нужно повторить название действия, которое показано в карточке. Сравниваются основы слов: окончания не важны, латиница сравнивается как кириллица («Telegram» = «телеграм»). Глагол засчитывается только в неопределённой форме или в повелительном наклонении. Имя адресата сохраняет род: «Валентине» не подтверждает «Валентин». Короткие слова и цифры названия нужно произнести целиком. Кроме названия во фразе допустимы только предлоги и согласие («да», «давай», «подтверждаю»). Отрицание или стоп-слово в любом месте фразы означает отказ, вопрос («?») не подтверждает (решение 0025).
- Голосовым сообщением из Telegram ответить на вопрос нельзя ни при каком риске: распознанный текст только начинает новый ход. Пока вопрос открыт, голосовое не распознаётся, а бот просит ответить кнопкой или текстом (решение 0029).
- Текстом из Telegram отвечают только на вопрос, карточка которого пришла в Telegram. На вопрос, открытый на компьютере, первое сообщение не отвечает: бот присылает карточку с кнопками, и ход продолжается в Telegram (решение 0031).

Голосовое подтверждение принимается только пока открыта карточка и только после окончания собственной речи помощника. Активационная фраза, сказанная во время её речи, обрывает речь. С Vosk речь обрывают и слова «стоп», «хватит», «замолчи», «тихо», а пока она слушает и говорит, другие программы звучат тише (решение 0024). Пока текущий ответ содержит её имя, фраза пропускается, чтобы её голос из динамиков не будил её саму (решение 0012). Сейчас голосовой ввод идёт по нажатию, и начало записи обрывает речь помощника, поэтому её собственные слова в микрофон не попадают (решение 0010). Для высокого риска кнопка «Разрешать всегда» недоступна. Без ответа в течение 60 секунд действие отклоняется.

### «Слепая зона»

Если заголовок активного окна похож на пароль, вход, банк, оплату, двухфакторный код или кошелёк, просмотр экрана и действия в этом окне приостанавливаются. Проверяется только заголовок, поэтому в настройках это описано честно. В браузере Мики проверяются ещё адрес страницы и поле пароля на ней (решение 0014). Диктовка сверх заголовка проверяет, не стоит ли курсор в поле пароля; если узнать это не удалось, она отказывает (решение 0030). Признаки проверяются по-русски и по-английски всегда, каким бы ни был язык интерфейса (решение 0035). В журнал приложения из такого окна не попадает ничего, даже когда запись текстов включена (решение 0036). Полоса вкладок такого окна не читается; вкладка с названием из «слепой зоны» не открывается и не называется; окно, чья открытая вкладка в «слепой зоне», считается окном «слепой зоны» (решение 0038).

Запись экрана смотрит не только активное окно, а все окна на экране в области записи, вместе с диалогами: впереди они или под другими окнами. Запись не начинается, пока такое окно видно. Если оно появилось во время записи, запись встаёт на паузу вместе со звуком, а кусок обрезается за 0,75 секунды до момента, когда окно замечено; в итоге Мика говорит, сколько было пауз (решение 0032).

### Действия самого пользователя

Голосовой вопрос, выделенный текст, диктовку и вопрос про экран начинает пользователь нажатием клавиш. Карточки подтверждения у них нет: политика стоит между моделью и действием, а здесь действует сам пользователь. Запреты остаются и проверяются в коде действия до любого шага: выключатели «Микрофон» и «Экран», выключатель самого действия, «слепая зона». Диктовка и вопрос про экран пишутся в журнал действий со средним риском и пометкой «действие пользователя»; текст диктовки и вопрос в журнал не попадают (решение 0030).

Собственные нажатия Мики эти действия не запускают. Инструмент `ui_keys` и устройство ввода отказываются послать сочетание, которое зарегистрировано у Мики; сочетание, сработавшее в секунду после её собственных нажатий, не считается нажатием пользователя; пока идёт ход, диктовка и вопрос про экран отказывают. `ui_keys` останавливается, если впереди оказалось окно Мики или окно из «слепой зоны» (решение 0030).

## 9. Эмоции и аватар

### Слоты

Десять слотов, одинаковых для любой модели: спокойная, радость, смущение, удивление, грусть, сердится, думает, подмигивает, сонная, тревога.

### Источники

- Состояние приложения: думает, ждёт подтверждения, ошибка, успех.
- Метка эмоции в ответе LLM: слово в квадратных скобках, например `[joy]`. Метка вырезается до показа в чате и до озвучки и срабатывает, когда начинается озвучка её предложения. Пока голоса нет, она срабатывает сразу (решение 0008). Английские названия вроде `[smile]` понимаются как эмоции, а выдуманная метка из одного латинского слова в начале ответа просто вырезается (решение 0021). При выразительной речи с моделью Fish Audio Drama 3 ремарки в квадратных скобках и парные теги вроде `<whisper>` уходят в голос и вырезаются из показа, а метка эмоции из ремарки по-прежнему двигает аватар (решение 0026).
- События: долго без дела, похвала, ругань.

### Ядро эмоций

Выбирает одну эмоцию и её силу, держит несколько секунд и плавно возвращает к спокойной. Эмоция от опасного действия важнее метки из ответа.

Сделано в решении 0008: приоритеты (опасное действие, затем ошибка, затем метка и успех, затем состояние), удержание 4 секунды, «сонная» после 5 минут без дела. Силы эмоции в ядре нет: плавный вход и выход эмоции делает сцена модели (решение 0039).

Длинный ответ не зачитывается: звучит его короткий пересказ той же моделью. Что прозвучит целиком, решает сама модель: перед анекдотом, стихами, сказкой или текстом, который просили прочитать вслух, она ставит метку `[aloud]`, и такой ответ звучит полностью (решение 0037). Во время задачи по этапам звучит только итог или причина обрыва (решение 0025). Эмоция слышна и в голосе (решение 0025). Голос Windows меняет высоту и темп через SSML `prosody`, провайдеру уходит строка о настроении вместе с описанием голоса словами. Описание голоса задаёт пользователь. Копии голосов чужих персонажей и актёров не делаются. Без модели Мика здоровается после отсутствия, ночью говорит, что поздно, и радуется концу фокуса и сделанному делу (переключатель «Живость»).

С выразительной речью Drama 3 настроение слышно и там, где модель ничего не разметила. Фраза, в первой строке которой нет своей ремарки или тега, получает ремарку под текущую эмоцию, например `[cheerful, with a smile]` для радости или `[worried, serious]` для тревоги; для спокойной и «думает» ремарки нет. Ремарка ставится перед самым синтезом, поэтому её нет ни в чате, ни в истории, ни в тексте Telegram. Переключатель «Ремарка по настроению» выключен по умолчанию. Скорость и отдельный голос на каждую эмоцию у голосов провайдера не делаются: скорость понимают единичные модели, а другой голос — это другой персонаж (решение 0029).

### Встроенный аватар

Аватар по умолчанию — сгенерированная аниме-иллюстрация, по кадру на каждую из десяти эмоций (решение 0013). Слои глаз и рта дают моргание и движение губ в состоянии «отвечает», лёгкое покачивание даёт дыхание. Губы во время речи двигаются у всех эмоций: у каждой свой кадр с приоткрытым ртом (решение 0017). Каждая эмоция начинается движением тела, в покое она поглядывает в стороны и улыбается; клик по аватару в чате вызывает реакцию, которую выбирает ядро эмоций (решение 0015). Модель пользователя заменяет картинки, слоты и ядро эмоций те же (решение 0039). Если модель не показалась, показываются эти картинки.

### Слои на модели

Снизу вверх: дыхание и моргание, взгляд, губы под речь, эмоция, разовый жест. Слои складываются.

### Модели пользователя

Сделано для формата VRM (решение 0039). Live2D отложен.

- Пользователь добавляет файл `.vrm` на странице «Персонаж». Диалог выбора файла открывает само приложение, страница путей не знает. Моделей может быть несколько, выбрана одна.
- Файл проверяется при импорте и при каждой загрузке. Модель, которая ссылается на файлы или адреса вне себя, не принимается; загрузчик в интерфейсе тоже открывает только данные самого файла.
- Модели лежат в `%LOCALAPPDATA%\Mika\models`, по папке на модель. В копию для переноса файлы моделей не входят.
- Моргание, взгляд и губы работают через стандартные выражения и взгляд VRM. Дыхание, поза покоя и движение в начале эмоции делаются кодом: модель без анимации стоит с разведёнными руками.
- При импорте выражения модели сопоставляются со слотами: стандартное выражение, затем своё выражение модели по названию, затем смесь стандартных выражений и взгляда.
- Любой слот пользователь назначает вручную в таблице на странице «Персонаж», выбор сразу виден в предпросмотре.
- Соответствия сохраняются в файл профиля рядом с моделью.
- Значки показывают портреты модели, нарисованные один раз. Живая модель рисуется в колонке чата, в окне на рабочем столе и в предпросмотре настроек, одна сцена на окно. Сцена не рисуется, пока её окно не видно.
- Губы двигаются, пока состояние «отвечает», а не по громкости звука. Взгляд за курсором не сделан.
- Название, автор и условия использования из файла показываются пользователю. Приложение по ним ничего не запрещает.

### Размещение

Аватар показывается в развёрнутом островке, отдельно на рабочем столе поверх окон или в обоих местах. Выбор в настройках.

Окно на рабочем столе стоит в правом нижнем углу основного монитора и пропускает все щелчки. Рядом с аватаром облачко: что она делает, текст ответа, название действия, которое ждёт подтверждения.

## 10. Интерфейс

Точные размеры и поведение взяты из макета.

### Островок

Шесть форм, переход между ними пружинный:

| Состояние | Размер, px | Содержимое |
|---|---|---|
| Покой | 236 × 44 | Аватар-кружок, имя, время. Погода появится, когда будет задан город |
| Слушает | 340 × 52 | Волна голоса, подсветка по контуру |
| Думает | 380 × 52 | Что она делает, какой инструмент работает |
| Отвечает | 620 × 78 | Текст ответа по словам, выключатель озвучки |
| Чат | 860 × 500 (600 × 500 без аватара) | Аватар слева, чат справа |
| Подтверждение | 600 × 268; до 600 × 380, когда действие описано несколькими строками (решение 0032); до 600 × 440 у карточки сценария по событию, которая показывается целиком (решение 0031); в английском интерфейсе на 21 выше, пока над описанием стоит строка «описание пока на русском» (решение 0035) | Карточка действия |
| Настройки | 860 × 500 | Панель разделов слева, страница справа |

Чат открывается щелчком по островку, из значка в области уведомлений или клавишами Ctrl+Alt+M (решение 0007). Сочетания всех действий собраны в один список и меняются на странице «Клавиши»; занятое сочетание и привычные команды правки (Ctrl+Shift со стрелками и с Z, V, C, T, N) назначить нельзя (решение 0030).

Во время диктовки островок в форме «Слушает» пишет «Диктовка», а пока текст распознаётся — «Распознаю…». Отказ диктовки или вопроса про экран островок показывает сразу, и пока Мика думает или говорит (решение 0030).

В шапке чата всегда видны переключатели «Озвучка», «Микрофон», «Экран», кнопки «Открепить» и «Настройки». Под каждым ответом видно выполненное действие и его время. Результат погоды показан карточкой, смена громкости — полоской уровня.

Если прошлый запуск не завершился чисто (падение, снятый процесс, выключение питания), чат один раз показывает спокойную строку со ссылкой «Открыть журнал» и кнопкой «Скрыть» (решение 0036).

Фоновое задание показано в чате карточкой: что делается, состояние, проценты, кнопка «Стоп», в конце — итог и файлы. Пока идёт запись экрана, на островке и на значке в области уведомлений горит красная точка, а в меню значка есть «Остановить запись»; в режиме обычного окна точка стоит на верхнем краю окна (решение 0032).

«Озвучка», «Микрофон» и «Экран» работают. «Микрофон» только разрешает запись: она начинается кнопкой в поле ввода или клавишами Ctrl+Alt+K (решение 0010). «Открепить» превращает островок в обычное окно, в окне она называется «Закрепить» (решение 0011).

### Режимы окна

1. Закреплён сверху на основном мониторе, поверх всех окон. Режим по умолчанию.
2. Островок на другом мониторе: его перетаскивают, и он прилипает к верхнему краю того монитора, где его бросили. Монитор можно выбрать и на странице «Островок».
3. Обычное окно со свободным размером: чат и настройки занимают его целиком, колонка аватара пропадает в узком окне.

Рамки Windows нет ни в одном режиме: шапку и края рисует страница. Островок, брошенный ниже верхнего края, становится обычным окном; обычное окно, брошенное к самому верху, снова становится островком. Двойной щелчок по шапке окна разворачивает его на весь экран (решение 0012). Свёрнутый островок тянется за любое место, открытый чат и настройки — только за верхнюю часть. Меню браузера по правой кнопке выключено везде, кроме полей ввода (решение 0015).

Выбранный монитор, место и размер обычного окна запоминаются.

Пока впереди игра, видео или программа, развёрнутая на весь монитор, островок и аватар уходят назад, за неё. Ctrl+Alt+M, Ctrl+Alt+K, активационная фраза и вопрос о действии выводят их вперёд. После вызова они остаются впереди, пока она отвечает или пока её окно в фокусе. Это отключается на странице «Островок» (решение 0012).

При первом запуске открывается экран из двух шагов: провайдер, затем что ей можно; всё выключено, пока пользователь не включит. На этом же экране стоит переключатель языка «Русский / English»; первый запуск идёт за языком Windows (решение 0035). Ссылка «У меня есть копия с другого ПК» открывает восстановление из копии (решение 0034).

### Настройки

Разделы: Персонаж, Провайдеры, Разрешения, Инструменты, Память, Расширения, Голос, Островок, Клавиши, Расходы, Журнал, Общие. Содержимое «Персонажа», «Провайдеров» и «Разрешений» показано в макете. Настройки открываются внутри островка (решение 0008).

Поле любой модели (основной, зрения, картинок, эмбеддингов, синтеза и распознавания речи) можно заполнить из списка провайдера. В списке: цена, контекст, умеет ли модель вызывать инструменты, описание; отбор под назначение. Имя голоса выбирается из списка провайдера, а если провайдер его не отдаёт — из известных голосов семейства модели (решение 0016).

- «Инструменты»: интернет, просмотр экрана, лента новостей, FFmpeg (найденный путь и версия, свой путь, «Скачать» и «Удалить» для копии Мики) (решение 0027), группы инструментов.
- «Инструменты», блок «Глубокий поиск»: модель для поиска (пусто — основная), папка отчётов, лимиты одного поиска: поисков, страниц, минут, токенов (решение 0033).
- «Память»: факты, архив разговоров, модель эмбеддингов.
- «Расширения»: свои команды, напоминания и расписание, серверы MCP, Telegram.
- «Расширения», блок «Сценарии по событию»: общий выключатель, список сценариев с выключателем и удалением, список «Сейчас слежу» с кнопкой остановки. Сценарий создаётся в чате или голосом (решение 0031).
- «Голос»: озвучка, движок (голос Windows или провайдер), модель и голос синтеза, «Выразительная речь» для Fish Audio Drama 3 (решение 0026), микрофон, модель и язык распознавания, адрес и ключ провайдера речи, проверка микрофона.
- Добавлено решением 0029. «Расширения», блок Telegram: «Принимать голосовые сообщения» и «Отвечать на голосовые голосом». «Голос»: «Ремарка по настроению». Все три выключены по умолчанию.
- «Островок»: город для погоды, скрытие в полноэкранных программах, монитор. Этот же город берёт инструмент погоды, когда пользователь не назвал город; если город не задан и не назван, Мика его спрашивает.
- «Расходы»: выключатель учёта; сегодня и текущий месяц с полосами бюджета; расходы по видам и по моделям; лимиты на день и на месяц и их валюта; выключатель «На 100% не начинать платную работу самой» и строка о том, что пауза идёт сейчас; своя цена для модели, у которой провайдер цену не сообщает; «Обновить цены» и «Стереть учёт» (решение 0028).
- Вечерний итог дня настраивается на странице «Инструменты» под утренней сводкой: выключатель, время и «Показать сейчас» (решение 0028).
- «Клавиши»: сочетания пяти действий (чат, голосовой вопрос, выделенный текст, диктовка, вопрос про экран) с кнопками «Изменить» и «Вернуть»; выключатели «Диктовка в любое окно» и «Вопрос про экран» с текстом о том, что звук фразы и снимок окна уходят провайдеру (решение 0030).
- «Журнал»: список записей от новых к старым по 100 с кнопкой «Показать ещё» (на странице не больше 1000), отбор по уровню и категории, поиск по тексту, переключатель «Следить» (новые записи появляются сами, пока страница открыта), раскрытие длинной записи и копирование. Кнопки «Сохранить в файл» (окно Windows «Сохранить как», один текстовый файл с шапкой без секретов), «Открыть папку», «Очистить» (вторым нажатием). Блок «Что записывать»: подробность, «Писать тексты и аргументы» с предупреждением перед включением, срок хранения в днях. Строка о размере: сколько журнал занимает, сколько файлов, с какого дня (решение 0036).
- «Общие»: язык интерфейса (решение 0035), автозапуск, папки, «Сообщить о проблеме» (текст для копирования, ничего не отправляется: версия, Windows, настройки без секретов, последние 200 записей журнала и ошибки за сутки, решение 0036), перенос на другой ПК (сохранить копию с паролем или без, восстановить из копии с предпросмотром) (решение 0034), удаление данных.

«Персонаж»: имя, характер (заботливая, весёлая, спокойная, дерзкая или свой текст), где показывать аватар, просмотр десяти эмоций.

Тексты интерфейса лежат в `frontend/src/locales/`: `ru.json` и `en.json`.

### Язык интерфейса

Языков два: русский и английский (решение 0035). Английские тексты лежат в `frontend/src/locales/en.json` с теми же ключами и подстановками, что в `ru.json`; за этим следят тесты. Оба файла вшиты и в интерфейс (`frontend/src/lib/locale.svelte.ts`, из него берут тексты страницы), и в ядро: Rust читает те же файлы через `mika_core::i18n` — меню значка, ошибки команд, её реплики без модели.

- Настройка `i18n.language`, по умолчанию `ru`. У существующих пользователей язык не меняется. Первый запуск (нет ни `config.toml`, ни базы данных) идёт за языком интерфейса Windows: русский даёт `ru`, любой другой — `en`. Новый профиль видит экран первого запуска, даже если остался ключ от прежней установки.
- Язык меняется без перезапуска на экране первого запуска и на странице «Общие»; все окна переключаются сразу. Ключа нет в `en.json` — показывается русский текст.
- Пока первый запуск не пройден, вместе с языком меняются имя по умолчанию («Мика» или «Mika»), имя для отклика и язык распознавания, если пользователь их ещё не менял. После первого запуска переключатель меняет только язык.
- При английском интерфейсе основа системной подсказки и характеры английские, а Мика отвечает на языке сообщения пользователя, по умолчанию по-английски. Описания инструментов и подсказки модели остаются русскими. Голос Windows в режиме «Авто» берёт голос языка, на котором она отвечает: при русском интерфейсе русский, при английском — языка речи из настроек голоса (английский, если он не задан).
- Карточка подтверждения, строки инструментов и часть ошибок записаны в коде Rust и пока остаются русскими. Об этом говорят страница «Общие», экран первого запуска, пока выбран английский, и строка на самой карточке над русским описанием. Итог дня, ответ на вопрос про экран и отчёт глубокого поиска тоже пока пишутся по-русски: их подсказки модели требуют русского. Счёт, полный список и порядок переноса — в решении 0035.

### Стиль

Тёмное стекло, чёрный островок, три акцентных цвета: фиолетовый `#8f7dff` (состояние «слушает»), розовый `#ff7eb6`, голубой `#6fe3ff` (инструменты). Красный `#ff6b7d` только для опасности.

## 11. Провайдеры

Четыре интерфейса в `mika-providers`: ответы (LLM), распознавание речи, синтез речи, картинки. Каждый поддерживает потоковую работу там, где провайдер её даёт.

Первые адаптеры:

- LLM: любой OpenAI-совместимый адрес, Anthropic, Ollama. Ollama подключается через свой OpenAI-совместимый адрес `/v1` (решение 0006).
- Погода: Open-Meteo. Поиск: HTML-версия DuckDuckGo. Оба без ключа (решение 0006).
- Глубокий поиск: внутренние обращения идут той же LLM или отдельной моделью из настроек, без инструментов, с обрывом ответа на пределе длины; счёт токенов — оценка по числу знаков, в него входят и рассуждения, которые модель пишет в ответе. Брошенный запрос к провайдеру закрывает соединение сразу, даже пока модель молчит. Поисковик и страницы читает отдельный клиент: без прокси и кук, соединение только с адресами открытого интернета, каждая переадресация проверяется заново (решение 0033).
- Синтез речи: голос Windows локально (решение 0009) или адрес `/audio/speech` провайдера (решение 0010).
- Выразительная речь: с моделью, в имени которой есть `drama` (`fish-audio/drama-3` в RouterAI), Мика размечает ответ ремарками `[...]` и семью парными тегами. Разметку получает только голос провайдера, голос Windows и все места показа получают чистый текст. Текст не из ответа модели (уведомления, напоминания, ошибки) уходит провайдеру со скобками `[ ]`, заменёнными на `( )`, чтобы Fish не принял его за ремарку; ответы модели без разметки уходят как раньше (решение 0026).
- Синтез речи у провайдера заказывается не дальше двух фраз вперёд от играющей; «Стоп» и выключение озвучки отменяют остальное, а при выключенном звуке Windows речь не синтезируется вовсе (решение 0018).
- Звук провайдера хранится на диске, до 100 МБ: повторная фраза тем же голосом не заказывается снова. Выключатель и кнопка «Забыть фразы» есть в разделе «Голос» (решение 0019).
- Распознавание речи: адрес `/audio/transcriptions` провайдера (решение 0010). Файлы распознаются кусками до 60 секунд; для субтитров время фраз берётся из `verbose_json`, а если провайдер его не даёт — звук режется по паузам (решение 0027).
- Голосовые Telegram. На распознавание звук уходит как пришёл: OGG с Opus под именем `voice.ogg`. Если провайдер отказал запросу и найден FFmpeg, звук переводится в WAV 16 кГц моно, как у микрофона. Для ответа синтез просят отдать MP3 (`response_format`); провайдер, который отказал, получает запрос без этого поля. MP3, M4A и OGG с Opus уходят голосовым сообщением. WAV и остальное FFmpeg переводит в OGG с Opus, а без FFmpeg они уходят звуковым файлом. Ответ — один запрос синтеза не длиннее 500 знаков слов и 250 знаков разметки; звук Windows на него не влияет. Разметку для такого ответа модель пишет и при выключенной озвучке на компьютере (решение 0029).
- Диктовка: одна фраза до 45 секунд — один запрос распознавания тому же провайдеру. Запрос не уходит, если речи не было или печатать некуда: окна впереди нет, оно в «слепой зоне» либо курсор в поле пароля. Повторов нет. Текст печатается как есть, модель его не правит (решения 0018, 0030).
- FFmpeg: свой по пути из настроек или в PATH, иначе сборка LGPL v3 с github.com/FFmpeg-Builds, закреплённая по тегу конца месяца, скачивается только по кнопке и проверяется по SHA-256. Мика запускает FFmpeg отдельной программой и не распространяет его (решение 0027).
- Активационная фраза: локальная модель Vosk (`vosk-model-small-ru-0.22`) распознаёт речь всем словарём, имя будит Мику только целым словом. Модель и библиотека скачиваются кнопкой в разделе «Голос» и проверяются по SHA-256. Пока их нет, имя слышит распознаватель Windows со списком фраз. Звук не покидает компьютер, команду после имени распознаёт провайдер (решения 0012, 0020).
- Разговор голосом: если вопрос задан голосом, после ответа Мика дожидается конца своей речи и снова слушает. Тишина, текст в чате или «Стоп» заканчивают разговор. Выключатель «Слушать после ответа» в разделе «Голос» (решение 0021).
- Обновления: файл описания версии по адресу https, проверка SHA-256 установщика, установка только по кнопке (решение 0012).
- Картинки: OpenAI-совместимый адрес `/images/generations`.
- Зрение: та же LLM или отдельная модель со зрением, картинка уходит в сообщении. Кадры видео уходят одним сообщением, от 2 до 12 картинок (решение 0027). Вопрос про экран по сочетанию клавиш — один запрос с одним снимком окна до 1600 точек, мимо основной модели; вопрос и ответ попадают в историю без картинки (решение 0030).
- Эмбеддинги: OpenAI-совместимый адрес `/embeddings`.
- Учёт расходов: счётчик стоит в адаптерах, поэтому любой вызов через них считается сам. Ответы и зрение — `usage` из потока (пока учёт включён, запрос просит `stream_options.include_usage`; отказ 400 или 422 повторяется без него, и учёт не роняет запрос), озвучка — знаки отправленного текста, распознавание — `usage.seconds` или длина отправленного звука (WAV по заголовку, голосовое Telegram в Ogg/Opus по страницам файла), эмбеддинги — `usage.prompt_tokens`, картинки — штуки. Цена: `usage.cost` из ответа (RouterAI, OpenRouter), иначе `pricing` из списка моделей провайдера, иначе цена из настроек, иначе только единицы. Список цен читается не чаще раза в сутки и только после платного вызова к этому адресу; после запуска — ещё раз при первом вызове к модели без сохранённой цены. Запрос списка идёт с ключом того раздела, который пользуется адресом. Локальный адрес стоит ноль; Ollama — на этом компьютере и в домашней сети. Ключи и тела запросов в учёт не попадают (решение 0028).

Зрение, картинки, эмбеддинги и речь по умолчанию используют адрес и ключ LLM; у картинок, эмбеддингов и речи можно задать свои.

В настройках у каждого провайдера есть кнопка «Проверить» и измеренная задержка.

## 12. Стиль кода

Взят у Priler/jarvis как подход, без копирования кода:

- рабочее пространство Cargo, версии зависимостей заданы один раз в `[workspace.dependencies]`;
- редакция 2021, стандартный `rustfmt` без своих настроек;
- модули в виде `foo.rs` рядом с папкой `foo/`, без `mod.rs`;
- ядро в отдельном крейте, отдельный крейт для терминала;
- журнал через `log`, блокировки через `parking_lot`, настройки в TOML;
- записи журнала английские, одной строкой; категория задаётся целью записи; текст пользователя или модели попадает в запись только через `journal::content`, `guarded` или `address`, текст ошибки инструмента или чужого сервера — через `guarded_error`, жалоба программы — через `complaint`; `error_text` только для слов самого приложения, системы и провайдера; секрет не форматируется никогда (решение 0036);
- тексты интерфейса вынесены в файлы локализации, первый язык русский, второй — английский (решение 0035).

## 13. Что проверяет эпик 0

Эти вопросы нельзя решить без пробной сборки. Ответы записываются в `docs/decisions/`.

1. Прозрачное окно-островок в Tauri 2: поверх всех окон, клики мимо островка проходят насквозь, несколько мониторов, разный масштаб.
2. Live2D в окне Tauri: скорость отрисовки, движение губ по звуку, загрузка модели из мастерской VTube Studio. Отдельно проверить упакованный формат Live2DViewerEX.
3. Голосовой цикл: какие локальные движки активационной фразы, распознавания и синтеза дают лучшую задержку на русском.
4. UI Automation из Rust: найти кнопку в чужом окне, нажать, ввести текст.
5. Лицензии: Live2D Cubism SDK и выбранных голосовых моделей.
