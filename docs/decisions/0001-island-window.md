# 0001. Окно-островок

Дата: 2026-11-10. Статус: принято с оговорками (часть проверок впереди, см. «Не проверено»).
Пробная сборка: `spikes/0001-island-window/`.

## Вопрос

Как сделать островок вверху экрана в Tauri 2: прозрачный, поверх всех окон, с клик-сквозь мимо островка, с плавной сменой формы?

## Что пробовали

Два способа в одной сборке, переключение переменной `SPIKE_MODE`.

1. **Холст** (`canvas`). Окно постоянного размера 900 × 540, прозрачное, без рамки. Островок меняет форму внутри него через CSS-переход. По умолчанию окно не принимает мышь (`set_ignore_cursor_events(true)`). Поток в Rust 60 раз в секунду читает положение курсора (`GetCursorPos`) и сравнивает его с прямоугольником островка, который присылает страница. Прямоугольник расширен на 4 px. Во время перехода страница присылает объединение старого и нового прямоугольника, по окончании — новый.
2. **Окно по размеру** (`resize`). Окно равно островку, страница на каждом кадре вызывает команду, которая меняет размер и положение окна.

Настройки окна: `decorations: false`, `transparent: true`, `shadow: false`, `alwaysOnTop: true`, `skipTaskbar: true`, `resizable: false`, `focus: false`, `visible: false` с показом из `setup`. Фон `html` и `body` прозрачный.

Проверка шла скриптом `spikes/0001-island-window/click_test.ps1` (запуск: `click_test.ps1 -Mode canvas -Out <папка>`): Блокнот под холстом, клики через `mouse_event`, после каждого клика читается заголовок окна на переднем плане, снимки экрана через `CopyFromScreen`.

## Среда

- Windows Server 2025, удалённый сеанс (адаптер Microsoft Remote Display Adapter).
- Один монитор 1920 × 1080, масштаб 100 %.
- Отладочная сборка.

Частота кадров в удалённом сеансе ограничена примерно 32 кадрами в секунду. Поэтому замеры плавности и нагрузки ниже не показательны для обычного компьютера.

## Результаты

### Прозрачность

Оба способа: прозрачные области окна полностью прозрачны, Блокнот под ними виден. В способе «холст» свечение вокруг островка рисуется. В способе «окно по размеру» свечение обрезано краем окна, а в углах скругления виден прямоугольный ореол.

### Клик-сквозь (способ «холст»)

| Клик | Ожидание | Итог |
|---|---|---|
| Прозрачная область над Блокнотом (700, 300) | Блокнот | Блокнот |
| Островок в покое (960, 36) | Островок, смена состояния | Островок, состояние сменилось |
| На 14 px ниже островка «Слушаю» (960, 80) | Блокнот | Блокнот |
| Внутри карточки подтверждения (960, 250) | Островок | Островок |
| Прозрачная область справа (1300, 400) | Блокнот | Блокнот |

Способ «окно по размеру» прошёл те же пять проверок.

### Стоимость (не показательна, см. «Среда»)

| | Холст | Окно по размеру |
|---|---|---|
| Процесс приложения в покое за 10 с | 250–297 мс | 0 мс |
| WebView в покое за 10 с (страница крутит счётчик кадров) | 62–94 мс | 78 мс |
| Худший разрыв между кадрами при смене формы | 31,4 мс | 31,4 мс |
| Самый долгий вызов изменения размера окна | — | 58 мс |
| Самый долгий шаг опроса курсора | 33–106 мс | — |

Изменение размера окна иногда занимает больше двух кадров. Это рывок при смене формы.

Шаг опроса курсора иногда ждал до 106 мс, то есть до шести кадров. Причина — чтение положения и масштаба окна на каждом шаге: эти вызовы идут через главный поток. Пока шаг ждёт, островок не реагирует на курсор. Это главный довод за кэширование в пункте 2 решения.

### Прочее

- Окно получило передний план при запуске, несмотря на `focus: false`. Причина не подтверждена: сборку запускал скрипт из активного процесса, а Windows разрешает такому запуску забрать передний план. При автозапуске поведение может отличаться.
- Клик по островку делает его активным окном. Фокус уходит из программы, в которой работал пользователь.
- В отладочной сборке рядом открывается консоль. Её нужно скрывать при проверках, иначе она перехватывает клики.

## Решение

**Холст постоянного размера с опросом курсора.** Он сохраняет свечение и пружинные переходы и не дёргает окно на каждом кадре.

Уточнения для продукта:

1. **Размер холста 1000 × 600 вместо 900 × 540.** Чат занимает 860 × 500, и при холсте шириной 900 свечение обрезается по 20 px с каждой стороны.
2. **Дешёвый опрос.** Кэшировать положение и масштаб окна и обновлять их по событиям перемещения и смены монитора, а не читать на каждом шаге. Когда курсор далеко от островка, опрашивать реже. Цель — меньше 1 % одного ядра в покое на обычном компьютере.
3. **Без кражи фокуса.** Показывать окно без активации: эпик 1, задача 5. В состояниях без поля ввода не активировать окно по клику, а поле ввода чата активирует окно, иначе в него не напечатать: эпик 6, когда появится чат.
4. **Объединение прямоугольников** во время перехода оставить: без него клик в середине анимации проходит насквозь.

## Что это меняет

- План эпика 1, задача 5: холст 1000 × 600, ожидаемые значения в тестах положения окна пересчитаны.
- Дизайн не меняется.

## Не проверено

Эти пункты нельзя проверить в удалённом сеансе с одним монитором. Их проверяет пользователь на своём компьютере после эпика 1.

1. **Два монитора с разным масштабом.** Основной 100 %, второй 150 %. Перенести островок на второй. Ожидание: размер островка в сантиметрах на обоих одинаковый, клики мимо островка проходят насквозь.
2. **Монитор слева от основного.** Ожидание: островок по центру его верхнего края, клик-сквозь работает.
3. **Полноэкранная игра и видео.** Запустить игру в полноэкранном режиме. Записать: виден ли островок, не сворачивается ли игра, не падает ли частота кадров.
4. **Плавность на 60 Гц и выше.** Сменить все формы клавишами 1–5. Ожидание: без рывков.
5. **Нагрузка в покое.** Диспетчер задач, 1 минута в покое. Ожидание: процесс приложения и WebView2 вместе меньше 1 %.
6. **Windows 10 19041.** Прозрачность и клик-сквозь.
7. **Alt+Tab.** Записать, виден ли островок в списке окон.
