# 0027. Видео и аудио файлы через FFmpeg

Дата: 2026-11-13. Статус: принято.

## Вопрос

Пользователь попросил, чтобы Мика работала с видео и аудио файлами через FFmpeg: меняла формат, сжимала, резала, склеивала, обрабатывала звук, распознавала речь в файле и рассказывала, что в видео. Нужно решить, откуда берётся FFmpeg, какие инструменты получает модель, какой у них риск и как не испортить файлы пользователя.

## Что решил пользователь

- FFmpeg ищется по пути из настроек и в PATH. Если его нет, Мика предлагает скачать сборку LGPL в `%LOCALAPPDATA%\Mika\ffmpeg`. Скачивание начинается только после явного «да» пользователя, архив проверяется по SHA-256. Установщик Мики не растёт.
- Возможности, все четыре группы:
  1. формат и сжатие: смена формата (webm → mp4, wav → mp3), сжатие до размера или качества, меньшее разрешение, звук из видео, сведения о файле (ffprobe);
  2. нарезка и склейка: кусок по времени, склейка нескольких файлов, GIF, поворот, ускорение и замедление;
  3. понимание содержимого: речь в текст и субтитры `.srt` тем же провайдером распознавания, что и для микрофона; «что в этом видео» по кадрам через модель зрения;
  4. обработка звука: выравнивание громкости, обрезка тишины по краям, шумоподавление, громкость, вшивание субтитров в видео.

## Откуда берётся FFmpeg

### Порядок поиска

При каждом вызове инструмента, без перезапуска:
1. путь из настроек `tools.ffmpeg_path`: файл `ffmpeg.exe` или папка, где лежит `ffmpeg.exe` либо `bin\ffmpeg.exe`;
2. папки из `PATH`, только абсолютные; текущая папка не просматривается;
3. скачанная Микой копия `%LOCALAPPDATA%\Mika\ffmpeg\ffmpeg.exe`.

`ffprobe.exe` должен лежать рядом с `ffmpeg.exe`, иначе эта находка не считается. Если путь из настроек задан, но по нему ничего нет, поиск идёт дальше, а страница «Инструменты» предупреждает об ошибке в пути.

Своя сборка пользователя, в том числе GPL с libx264, идёт раньше скачанной: в ней обычно больше кодеков.

### Скачивание с согласия

Если FFmpeg не найден, инструмент ничего не запускает и не спрашивает разрешения на действие. Модель получает ошибку «FFmpeg не найден», а в чате появляется карточка с кнопкой «Скачать». Такая же кнопка есть на странице «Инструменты». Нажатие кнопки и есть явное «да». Над кнопкой показан текст согласия:

> FFmpeg — отдельная программа проекта FFmpeg (ffmpeg.org) под лицензией LGPL v3. Мика скачает сборку FFmpeg 9.0 (161 МБ) с github.com/FFmpeg-Builds в %LOCALAPPDATA%\Mika\ffmpeg и проверит её по SHA-256. Мика не входит в проект FFmpeg.

Модель сама скачать FFmpeg не может: инструмента для этого нет. Команда из Telegram получает текст ошибки, кнопка есть только на компьютере.

### Закреплённая сборка

Сборки FFmpeg-Builds (бывший BtbN) хранятся так: последняя сборка месяца — два года, ежедневные — 14 дней, сборки `latest` заменяются каждый день. Поэтому закреплена сборка конца месяца:

| Что | Значение |
|---|---|
| Тег | `autobuild-2026-10-31-12-59`, хранится примерно до 2028-10 |
| Адрес | `https://github.com/FFmpeg-Builds/FFmpeg-Builds/releases/download/autobuild-2026-10-31-12-59/ffmpeg-n9.0.2-39-g7adfbe40dc-win64-lgpl-9.0.zip` |
| Размер | 168 715 328 байт |
| SHA-256 | `9d37c564e0d01c18cde184a079fa6ef04d7d2783ada41da81d04165cc8f1a650` |
| Папка внутри | `ffmpeg-n9.0.2-39-g7adfbe40dc-win64-lgpl-9.0` |

Сумма сверена дважды: по файлу `checksums.sha256` выпуска и по полю `digest` в API GitHub. Запасная сборка того же тега, линия 8.1: `ffmpeg-n8.1.3-27-g8dca1586f4-win64-lgpl-8.1.zip`, 167 778 744 байт, SHA-256 `d4c2a42673917b4a97104a3e9f082729a9730796b98664e37c0b7eba6c6c613d`. В коде она не используется. Сборку меняют в одном из следующих выпусков Мики, до конца срока хранения.

Как скачивается:
- только https; переадресация разрешена на `github.com`, `release-assets.githubusercontent.com` и `objects.githubusercontent.com`, не больше пяти переходов;
- размер должен совпасть с ожидаемым, лишние байты обрывают скачивание;
- сумма считается по ходу скачивания; не совпала — архив удаляется;
- из архива распаковываются только `bin/ffmpeg.exe`, `bin/ffprobe.exe` и `LICENSE.txt`. Распаковывает `tar.exe` Windows, он не выпускает файлы за пределы папки;
- работа идёт во временной папке рядом, старая копия заменяется только целиком готовой новой;
- архив после распаковки удаляется.

### Лицензия

Сборка LGPL — это LGPL версии 3: в ней нет libx264 и libx265. Мика не связывается с FFmpeg как с библиотекой, а запускает его отдельной программой. Мика не распространяет FFmpeg: пользователь скачивает его у издателя сборки. Поэтому архив нельзя класть в установщик или на свой сервер: так Мика стала бы распространителем со всеми обязанностями LGPL.

Где говорится о лицензии:
- текст согласия над кнопкой «Скачать»;
- строка на странице «Инструменты», пока есть скачанная копия: «Используется FFmpeg (ffmpeg.org) под LGPL v3, сборка github.com/FFmpeg-Builds, исходный код git.ffmpeg.org/ffmpeg.git, версия 7adfbe40dc»;
- `LICENSE.txt` лежит рядом с `ffmpeg.exe`.

Своя сборка пользователя может быть GPL. Страница «Инструменты» тогда пишет, что это сборка GPL. Для Мики это ничего не меняет: она запускает чужую программу.

## Инструменты

Новая группа `av`, «Видео и звук». Группа `media` уже занята плеером. Двенадцать инструментов:

| Инструмент | Что делает | Риск |
|---|---|---|
| `av_info` | Сведения о файле: длительность, размер, кодеки, разрешение, частота кадров, поворот, звук, дорожки субтитров | низкий |
| `av_convert` | Другой формат: mp4, mkv, mov, webm, mp3, m4a, wav, flac, ogg, opus. Звук из видео — это перевод в звуковой формат | средний |
| `video_compress` | Сжатие до размера в МБ или до качества «обычное» или «сильное», меньшее разрешение | средний |
| `av_cut` | Кусок по времени, точно или быстро по ключевым кадрам | средний |
| `av_join` | Склейка 2–20 файлов | средний |
| `video_gif` | GIF из куска видео до 30 секунд | средний |
| `video_rotate` | Поворот на 90, 180 или 270 градусов | средний |
| `av_speed` | Ускорение или замедление от 0,25 до 4 раз, звук без смены высоты | средний |
| `audio_process` | Выравнивание громкости, обрезка тишины по краям, шумоподавление, громкость | средний |
| `video_subtitles` | Вшить субтитры `.srt`, `.ass` или `.vtt` в видео | средний |
| `av_transcribe` | Речь в текст `.txt` и, по просьбе, субтитры `.srt` | средний; высокий, если звука больше 10 минут |
| `video_describe` | Что в видео: кадры уходят модели зрения | средний |

Почему так:
- `av_info` только читает файл. Как чтение файла, это низкий риск.
- Остальные инструменты пишут новый файл. Как у архивов (решение 0014), уровень — наибольший из двух: чтение исходника и запись результата. Обычная папка даёт средний риск, папки Windows и Program Files — высокий.
- `av_transcribe` и `video_describe` отправляют звук или кадры провайдеру. Об этом говорит причина в карточке подтверждения, как у `screen_look`.
- Распознавание платное. Больше 10 минут звука — высокий риск: такой вызов спрашивается всегда, и «всегда разрешить» для него нет. В карточке видно, сколько минут уйдёт провайдеру.
- Область правила «всегда» — пара папок: откуда читается и куда пишется, например `c:\видео -> c:\видео`. У склейки и субтитров в области все папки входов. Не пара файлов: иначе «всегда» сработало бы только для одного файла. Правило для одной папки результата не годится: «всегда» на расшифровке лекции из `D:\Видео` пропускало бы без вопроса отправку провайдеру записи из любой другой папки.
- Если `video_compress` видит, что файл уже меньше нужного размера, он ничего не пишет и спрашивается как низкий риск. У такой карточки своя область `check:<путь к файлу>`, и «всегда» на ней не разрешает сжатие с записью.

Звук из видео и меньшее разрешение отдельными инструментами не сделаны: это `av_convert` в звуковой формат и `video_compress` с высотой. Подсказки модели это называют. Двенадцать инструментов, а не двадцать, чтобы список для маленьких моделей оставался коротким.

## Правила безопасности

- **Только файлы этого компьютера.** Путь проходит ту же проверку, что у файловых инструментов: `%VAR%`, `~`, относительный путь от профиля, `..` сворачивается. Адреса со схемой (`http:`, `rtmp:`, `concat:`, `pipe:`, `data:` и другие), маски, пути устройств `\\.\` и двоеточие после буквы диска (скрытые потоки файла `x.mp4:y`) отклоняются до запуска FFmpeg. Сетевые папки Windows (`\\сервер\папка`) — это файлы, они разрешены.
- **Скрипты и плейлисты не открываются.** Сведения о файле ffprobe читает ещё до карточки подтверждения. Поэтому файлы `.avs`, `.avsi`, `.vpy` (скрипты AviSynth и VapourSynth: FFmpeg выполнил бы их), `.m3u`, `.m3u8`, `.mpd`, `.ffconcat` и `.sdp` отклоняются по расширению до запуска ffprobe.
- **Только обычные форматы.** Каждому входу ffprobe и FFmpeg передаётся `-format_whitelist` со списком разборщиков распространённых контейнеров видео и звука (mov/mp4, matroska/webm, avi, asf, flv, mpegts, mpeg, ogg, mp3, wav, flac, aac и другие). Файл, который FFmpeg принял за что-то вне списка, не читается дальше заголовка. Список склейки открывается с добавленным `concat`.
- **Никаких сетевых протоколов внутри FFmpeg.** Каждый вход передаётся как `file:<путь>` с `-protocol_whitelist file`, ffprobe тоже. Файлы, которые ffprobe определил как `hls`, `dash`, `concat`, `ffconcat`, `sdp` или `tee`, отклоняются: под видом `.mp4` может лежать плейлист.
- **Субтитры проверяются отдельно.** Фильтр `subtitles` сам угадывает формат файла и не знает о `-protocol_whitelist`. Поэтому копия субтитров во временной папке сначала читается ffprobe с `-format_whitelist srt,webvtt,ass`. Если формат не один из этих трёх, например XML плейлиста DASH под именем `.srt`, вызов отклоняется до запуска FFmpeg.
- **Без оболочки.** Аргументы FFmpeg собирает код, процесс запускается без cmd и PowerShell, без окна, с закрытым вводом (`-nostdin`). Текст модели не попадает в аргументы как есть: время, размер и числа разбираются и проверяются, форматы выбираются из списка.
- **Результат никогда не перезаписывает файл.** Имя по умолчанию строится рядом с исходником с пометкой, занятое имя получает ` (2)`. Если модель назвала существующую папку, результат кладётся в неё под именем по умолчанию. Если модель назвала результат, а такой файл уже есть, вызов отклоняется. Результат не может совпасть ни с одним входом.
- **Исходники не меняются и не удаляются.** Ни один инструмент не пишет в исходный файл.
- **Недоделанный файл не остаётся.** FFmpeg пишет во временное имя рядом, `-n` запрещает ему перезапись. Готовый файл переименовывается в конечное имя. При ошибке, по сроку и по «Стоп» процесс FFmpeg завершается, а временный файл удаляется. Удаление делает страж, который срабатывает и тогда, когда ядро бросило ожидание инструмента. Файл, ещё занятый умирающим процессом, удаляется повторными попытками до двух секунд.
- **Сроки.** Сведения о файле — 15 секунд. Перекодирование — 120 секунд плюс восемь длительностей файла, не больше 8 часов. Копирование без перекодирования — 60 секунд плюс четверть длительности. Перекодировать можно файлы до 4 часов, распознать — до 3 часов.
- **Ход работы.** FFmpeg сообщает, сколько обработано. Строка инструмента в чате показывает проценты, «Стоп» в чате останавливает работу.

## Кодеки

Выбор кодировщика H.264 для mp4, mov и mkv: libx264 (есть только в своей сборке GPL) → `h264_nvenc` → `h264_qsv` → `h264_amf` → `h264_mf` (Media Foundation Windows) → `libopenh264`. Кодировщики видеокарт и Media Foundation есть в списке даже без оборудования, поэтому каждый пробуется на секунде чёрного кадра. Итог запоминается для этого `ffmpeg.exe` по пути, размеру и времени изменения. Кодировщики Windows и видеокарт работают с кодеками, лицензированными через систему или драйвер.

webm кодируется в VP9 и Opus. Звук: AAC для mp4, mov и mkv, LAME для mp3, Opus для opus и webm, FLAC и PCM без потерь. Если кодеки входа подходят контейнеру, поток копируется без перекодирования: mkv → mp4 с H.264 занимает секунды. Таблица копирования следует тому, что FFmpeg умеет записать в каждый контейнер: AV1 копируется только в mp4 (в mov FFmpeg его не пишет), в WAV — только PCM с младшим байтом вперёд и G.711. Звук AIFF (`pcm_s16be`) в WAV перекодируется.

Кусок звукового файла копируется без перекодирования, только если FFmpeg умеет писать такой контейнер (mp3, m4a, wav, flac, ogg, opus, aac, ac3, aiff, wma, mka, wv и другие из списка). APE, DSF, Musepack FFmpeg только читает: их кусок кодируется в m4a.

Склейка без перекодирования требует, чтобы у всех файлов совпадали не только кодек, размер, частота кадров, частота и число каналов звука, но и профиль, уровень, формат точек, порядок кадров (`has_b_frames`), метка кодека и размер его настроек (`extradata`), а у звука — профиль (AAC-LC и HE-AAC) и формат отсчётов. Иначе результат хранит настройки первого файла, и вторая часть показывается испорченной. При любом расхождении файлы перекодируются. Тот же контейнер должен быть из списка, который FFmpeg пишет.

Субтитры для вшивания переводятся в UTF-8 без BOM: UTF-16 с BOM раскодируется, текст не в UTF-8 читается как Windows-1251, как часто сохранены русские `.srt`. Без этого фильтр с `charenc=UTF-8` не читает кириллицу.

## Понимание содержимого

### Речь в текст

FFmpeg переводит звук файла в WAV 16 кГц, моно, как у микрофона. Длина WAV ограничена `-t` той длительностью, которая была в карточке подтверждения, плюс секунда. Заголовок файла может показывать меньше, чем в нём есть звука, а запись может расти после карточки: провайдеру всё равно уходит не больше подтверждённого. Детектор тишины находит паузы, и звук режется по ним. Куски уходят тому же провайдеру распознавания, что и голос микрофона, по три запроса одновременно. Модель и язык распознавания берутся из раздела «Голос».

- Только текст: куски до 60 секунд.
- Субтитры: сначала распознаётся первый кусок с запросом времени фраз (`verbose_json`). Если провайдер вернул фразы со временем, так распознаются все куски до 60 секунд, а время сдвигается на начало куска. Если не вернул (так у части моделей), звук режется по паузам на фразы от 2 до 12 секунд, и каждая фраза — отдельный запрос и одна строка субтитров. Запросов больше, но оплачиваются, как правило, секунды звука.
- Кусок с ошибкой повторяется один раз. Вторая ошибка останавливает работу: уже распознанное сохраняется, и Мика говорит, до какого места дошла.
- Результат: `<имя>.txt` и при просьбе `<имя>.srt` рядом с файлом. Модель получает начало текста, не больше 3000 знаков, и пути к файлам.

### Что в видео

Кадры берутся равномерно по длительности, по умолчанию 6, не больше 12, шириной до 768 точек. Они уходят модели зрения одним сообщением, со временем каждого кадра в вопросе. Системная подсказка говорит, что это кадры одного видео по порядку, а не снимок экрана.

## Цена

- Распознавание платное, цена — за минуты звука. Больше 10 минут — высокий риск и подтверждение с числом минут. Больше 3 часов — отказ.
- Описание видео — один запрос к модели зрения с 2–12 картинками.
- Остальные инструменты работают только на этом компьютере и ничего не стоят.

## Не сделано

- Фоновые задания: пока FFmpeg работает, ход Мики ждёт его. «Стоп» прерывает работу.
- Обрезка тишины в видео: только в звуковых файлах. Для видео есть `av_cut`.
- Перебирание целых папок одним вызовом. Модель вызывает инструмент для каждого файла.
- Локальное распознавание речи (фильтр whisper в сборке выключен) и шумоподавление `arnndn` с отдельной моделью.
- Запись экрана и звука, потоки из интернета, скачивание видео с сайтов.
- Скачивание FFmpeg по просьбе в чате или из Telegram без кнопки.
- Автоматическая смена закреплённой сборки: её меняет новый выпуск Мики.

## Не проверено

- Какие провайдеры в RouterAI отдают время фраз в `verbose_json`. Без этого субтитры строятся по паузам.
- Скорость `h264_mf` и `libopenh264` на слабых машинах без видеокарты.
- Размер распакованных `ffmpeg.exe` и `ffprobe.exe`: страница показывает его после скачивания.
- Список `-format_whitelist` проверен по именам разборщиков FFmpeg, но не на живой сборке со всеми видами файлов. Редкий контейнер вне списка даст отказ «не читается как видео или звук».

## Что это меняет в дизайне

- §5 «Хранение»: `%LOCALAPPDATA%\Mika\ffmpeg`.
- §7 «Возможности»: пункт «Видео и звук».
- §10 «Настройки»: FFmpeg на странице «Инструменты».
- §11 «Провайдеры»: скачивание FFmpeg, распознавание файлов со временем фраз, кадры видео для модели зрения.
