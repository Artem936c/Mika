# 0011. Режим обычного окна и остатки эпиков 5, 9, 10

Дата: 2026-11-11. Статус: принято.

## Вопрос

Пользователь попросил продолжить разработку. Что из отложенного в решениях 0009 и 0010 можно сделать без пробных сборок и без решений пользователя?

## Решение

Сделаны четыре пункта: режим обычного окна (6.4), серверы MCP по HTTP (10.1), показ задержек этапов (5.10) с выбором микрофона (5.1), плеер в покое (9.7). План: [2026-11-11-remainders.md](../superpowers/plans/2026-11-11-remainders.md).

## Что сделано и как

1. **Обычное окно — это то же окно, а не второе.** Кнопка «Открепить» в шапке чата даёт окну заголовок, свободный размер и место в панели задач и снимает «поверх всех окон». Чат и настройки занимают окно целиком. Колонка аватара пропадает, когда окно уже 780 px. Наименьший размер 620 × 460.
2. **Крестик окна возвращает островок.** Приложение при этом не закрывается: выход остаётся в меню значка.
3. **Место и размер окна запоминаются.** Сохранённое место используется, только если заголовок окна попадает на подключённый монитор; иначе окно встаёт по центру размером 920 × 640.
4. **Обычное окно не прячется в полноэкранных программах**: оно не лежит поверх них.
5. **Перетаскивание островка не сделано.** Монитор островка по-прежнему выбирается на странице «Островок». Позже сделано вместе с отказом от рамки Windows, см. [решение 0012](0012-drag-wake-updates.md).
6. **MCP по HTTP** — транспорт streamable HTTP: запрос уходит методом POST, ответ читается из тела JSON или из потока событий, заголовок `Mcp-Session-Id` из ответа на `initialize` передаётся дальше. В поле сервера на странице «Расширения» адрес `http…` пишется вместо команды запуска. Вход по токену и OAuth не сделаны: сервер, которому нужен заголовок авторизации, не подключится.
7. **Задержки этапов** приходят событием `Timing` и видны строкой под ответом: распознавание, первое слово модели, первый звук. Первое слово считается от отправки запроса провайдеру, первый звук — от готовности первой фразы до начала её проигрывания. Времена пишутся и в журнал.
8. **Устройство записи** выбирается на странице «Голос». Если выбранное устройство пропало, берётся устройство по умолчанию.
9. **Плеер в покое.** Пока что-то играет, островок показывает название трека вместо имени. Состояние покоя опрашивается раз в 15 секунд.

## Проверено вживую

Машина разработки, 2026-11-11.

| Что | Итог |
|---|---|
| «Открепить» в окне приложения | Окно 920 × 640 с заголовком, чат на всё окно, кнопка стала «Закрепить», кнопки «Свернуть» нет |
| «Закрепить» | Островок 1000 × 600 вверху экрана, режим и место окна записаны в `config.toml` |
| Повторное открепление | Окно вернулось в сохранённый размер |
| Ответ при озвучке через провайдера | Под ответом строка «первое слово 1,5 с · первый звук 1,4 с», те же числа в журнале |

## Не проверено

- **Перетаскивание, изменение размера и крестик окна мышью.** Режим переключался командами через отладочный порт.
- **Запуск приложения сразу в режиме окна** и окно на втором мониторе.
- **MCP по HTTP с настоящим сервером.** Клиент проверен на поддельном сервере: ответ JSON, ответ потоком событий, передача сеанса, ошибки 401 и JSON-RPC.
- **Выбор микрофона и трек в покое.** На машине нет ни устройства записи, ни запущенного плеера: список устройств пуст, трек не приходит.
- **Задержка распознавания в чате.** Событие публикуется только после записи с микрофона.
