# 0022. Переписка в Telegram и других чатах

Дата: 2026-11-12. Статус: принято.

## Вопрос

Пользователь попросил Мику написать Алексею в Telegram и прислал, что вышло:

1. `open_app` не нашёл Telegram в меню «Пуск». Мика открыла его через PowerShell.
2. После восьми запросов к модели Мика остановилась: «слишком много шагов подряд».
3. Каждое сообщение ушло дважды («Привет», «Как дела тоже»), одно — с приклеенным старым текстом поля («ОнКак дела тоже»).
4. В «Как дела? 😊» смайлик встал посреди слова: «Ка😊к дела?».
5. Мика не видела ответов Алексея, хотя они были на экране.

## Причины

1. Telegram стоит из Microsoft Store: у таких программ нет ярлыка в папках меню «Пуск», их знает только список приложений Windows.
2. Без плана задачи было 8 запросов к модели, а на открыть, найти чат, ввести и проверить их нужно больше.
3. Telegram не показывает через UI Automation, что сообщение ушло. Модель не видела перемен и повторяла ввод. Поле перед вводом не очищалось.
4. Смайлик вне основной плоскости Юникода передаётся двумя событиями клавиатуры, и Telegram ставит его не туда.
5. Telegram рисует переписку сам: через UI Automation видны кнопки и список чатов, но не текст сообщений.

## Решение

1. **Программы из Store.** Если ярлыка нет, `open_app` ищет программу в списке `Get-StartApps` (читается один раз, около секунды) и открывает её как `shell:AppsFolder\<AppID>`.
2. **Уже открытая программа.** Если запустить нечего, а окно программы открыто, `open_app` выводит его вперёд вместо ошибки.
3. **Лимит без плана** — 14 запросов к модели вместо 8. С планом по-прежнему 40.
4. **Отправка в чат.**
   - `ui_type` с `enter` и без номера поля сначала очищает поле (Ctrl+A, Delete). Параметр `clear` меняет это поведение.
   - Тот же текст в то же окно с Enter второй раз за 90 секунд не уходит: модель получает ответ «уже отправлено, проверь окно». Повторить можно с `again=true`, только по просьбе пользователя.
5. **Смайлики.** Текст со смайликами и другими символами вне основной плоскости вставляется через буфер обмена (Ctrl+V). Прежний текст буфера возвращается на место.
6. **Чтение переписки.** `ui_read` говорит, что текст сообщений Telegram, Discord и похожих программ читается `screen_text` (распознавание на этом компьютере, только при включённом «Экране»). Это же правило есть в описании `ui_read` для всех программ.

## Проверено

- Тесты: Telegram из Store находится и открывается через `shell:AppsFolder`; уже открытый Telegram выводится вперёд; неизвестная программа — ошибка.
- Тесты: сообщение со смайликом очищает поле, вставляется через буфер, буфер возвращается; повтор того же сообщения отклоняется, с `again` проходит; обычный ввод без Enter поле не трогает.
- `Get-StartApps` на машине разработки отдаёт программы с русскими названиями без искажений.
- С настоящим Telegram не проверено: на машине разработки его нет.

## Что это меняет в дизайне

Раздел 7, «Цикл агента»: лимит без плана 14. Раздел «Окна программ»: Store-программы, ввод в чатах, чтение самодельных окон через `screen_text`.

## Дополнение: проверка других программ и браузера

Пользователь попросил проверить другие программы и браузер. Живые прогоны на Gemma 4 26B: Блокнот, Калькулятор, Центр отзывов из Store, «Параметры», Википедия. Найдено и исправлено:

1. **Очистка поля только в мессенджерах.** В 0.2.0-pre.3 `ui_type` с Enter нажимал Ctrl+A и Delete в любом окне, а в Блокноте или Word это стёрло бы документ. Теперь поле очищается, и повтор блокируется, только в мессенджерах (Telegram, WhatsApp, Discord, Viber, Slack, Teams, Skype, Signal, Element).
2. **Браузер.**
   - Окно Edge открывается шириной 1280 px: в узком окне Википедия прячет поиск, и Мика вводила текст во флажок.
   - `browser_type` вводит только в текстовые поля, а в флажок, кнопку или ссылку отвечает ошибкой.
   - Если после Enter страница осталась прежней, форма отправляется так же, как её отправила бы кнопка.
   - Скрипт на странице ждётся 10 секунд, а не 30. Прокрутка после неответа повторяется на новом соединении.
   - Edge запускается через оболочку и не наследует дескрипторы Мики, иначе вывод `mika-cli` не закрывался.
3. **Окна.**
   - Окно находится по словам запроса («Блокнот*» → «*Безымянный – Блокнот»), звёздочка предпочитает несохранённое окно.
   - «Параметры» находят окно «Настройки».
   - Номер элемента вместе с подписью или точкой больше не ошибка: побеждает номер.
   - Кнопка, которая отказалась нажиматься через UI Automation (меню закрылось под ней), нажимается мышью.
   - У списков WinUI без значения видна подсказка раскрыть их, чтобы увидеть выбор.
4. **Агент.** Служебные токены Gemma (`<|tool_call>`) вырезаются из текста, а пустой ответ, даже без инструментов, получает напоминание.

Проверено живыми прогонами:
- текст со смайликом в Блокноте встал целиком;
- Блокнот закрыт без сохранения: Мика нажала «Не сохранять» в диалоге;
- Калькулятор: 125 × 8 = 1000, окно закрыто;
- Центр отзывов открыт через `shell:AppsFolder`;
- Википедия: найдена статья «Пермь», ответ «1723».

Тесты:
- живой тест браузера: флажок не принимает ввод, форма отправляется, если Enter не сработал;
- тесты выбора окна и разбора параметров нажатия.
