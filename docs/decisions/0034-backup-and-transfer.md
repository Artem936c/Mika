# 0034. Копия и перенос на другой ПК

Дата: 2026-11-14. Статус: принято.

## Вопрос

Пользователь попросил перенос Мики на другой компьютер: сохранить всё своё в один файл и восстановить из него. Нужно решить, что входит в файл, как в нём лежат ключи, как устроено восстановление и как Мика защищается от чужого или испорченного файла.

## Что решил пользователь

- Ключи тоже хранятся в копии.
- Ключи попадают в копию только зашифрованными паролем, который вводит пользователь. В открытом виде они не касаются диска, журнала и текста ошибок. Без пароля копия делается без ключей и прямо говорит об этом.

## Что входит в копию

Просмотрены все места, где Мика держит данные.

| Где лежит | Что это | В копию |
|---|---|---|
| `%APPDATA%\Mika\config.toml` | Все настройки: имя и характер, свой текст характера, голос, модели и адреса провайдеров, островок, инструменты и выключенные группы, ритм и перерывы, сводка и вечерний итог, календарь, серверы MCP, владелец Telegram, папки документов, путь к FFmpeg, сочетания клавиш, лимиты и свои цены расходов, пределы глубокого поиска, язык интерфейса | да, целиком |
| `mika.db`, таблица `messages` | Переписка и архив прошлых разговоров | да |
| `facts` | Факты памяти | да, без векторов |
| `notes`, `todos` | Заметки и дела | да |
| `reminders` | Напоминания, таймеры, задачи по расписанию | да, только открытые; напоминания и задачи восстанавливаются раздельно, номера записей выдаются заново |
| `commands` | Свои команды | да |
| `rules` | Правила разрешений: запреты и «разрешать всегда» | да; восстанавливаются раздельно |
| `audit` | Журнал решений о действиях | нет: это журнал этого ПК |
| `message_vectors`, столбцы `embedding` у фактов | Векторы для поиска по смыслу | нет: кэш, Мика считает их заново при первом поиске |
| `doc_files`, `doc_chunks` | Указатель документов | нет: кэш по папкам этого ПК |
| `app_usage` | Время в программах | нет: статистика этого ПК |
| `cost_usage`, `cost_prices`, `cost_alerts`, `day_log` (эпик 16) | Учёт расходов, цены моделей, отметки бюджета, журнал дня | нет: статистика и журнал этого ПК |
| `triggers` (эпик 19) | Сценарии по событию | да, свой раздел; без выключателя и счётчиков, восстанавливаются выключенными |
| `trigger_runs` (эпик 19) | Запуски сценариев: по ним считаются пауза и пределы | нет: счёт этого ПК |
| Windows Credential Manager, служба `Mika` | Ключи, список ниже | только в зашифрованную копию |
| `%APPDATA%\Mika\browser\` | Профиль браузера Мики | нет: в нём входы на сайты, а куки привязаны к учётной записи Windows этого ПК и на другом не откроются |
| `%APPDATA%\Mika\backups\` | Копия прежних данных перед восстановлением | нет |
| `%LOCALAPPDATA%\Mika\logs`, `speech-cache`, `vosk`, `ffmpeg` | Журнал, кэш фраз, модель Vosk, FFmpeg | нет: кэш или скачивается заново по кнопке |
| `Изображения\Mika`, `Изображения\Screenshots` | Картинки и снимки экрана | нет: это обычные файлы пользователя |
| `Документы\Mika\Research` или своя папка, записи экрана и звука | Отчёты глубокого поиска (эпик 21), записи (эпик 20) | нет: это обычные файлы пользователя |
| Реестр, автозапуск | Запуск вместе с Windows | нет: путь к программе у каждого ПК свой |
| Память процесса | История буфера обмена, фокус, слежение за чатами, план задачи, слежения «подожди и скажи» (эпик 19), очередь фоновых заданий и идущая запись (эпик 20), счёт глубоких поисков за сутки (эпик 21), снимок окна для вопроса про экран (эпик 18) | нет: на диск не пишется |

Ключи, которые Мика хранит в Credential Manager:

| Имя записи | Что это |
|---|---|
| `llm.openai.api_key`, `llm.anthropic.api_key`, `llm.ollama.api_key` | ключ модели, свой у каждого вида провайдера |
| `speech.api_key`, `image.api_key`, `embedding.api_key` | ключи речи, картинок и эмбеддингов |
| `telegram.bot_token` | токен бота Telegram |
| `calendar.ics_url` | ссылка календаря ICS: она сама и есть секрет |
| `mcp.<имя сервера>.token` | токен сервера MCP по адресу |

Других записей у Мики нет: эпики 16–23 новых ключей не добавили. Список теперь один, в `mika-core`: по нему копия собирает ключи, а «Удалить все данные» их стирает. Попутно найдено: удаление данных пропускало `calendar.ics_url`; с общим списком это исправляется.

Копия делается всегда целиком. Выбор разделов есть при восстановлении, там он нужнее.

## Формат файла

Один файл с расширением `.mikabackup`. Имя по умолчанию: `mika-backup-2026-11-14.mikabackup`.

1. Восемь байт `MIKA-BKP`, затем номер формата (сейчас 1) и длина заголовка.
2. Заголовок: JSON открытым текстом, не больше 64 КБ. В нём версия Мики, дата, имя компьютера, зашифрован ли файл, сколько в нём ключей и параметры шифрования. Заголовок нужен, чтобы показать «что это за файл» до ввода пароля.
3. Тело: поток gzip, внутри строки JSON, по одной записи в строке. Сначала настройки (текст `config.toml`), затем ключи, затем таблицы: строка с именем таблицы и столбцами, за ней строки данных. Последняя строка — «конец» со счётчиком строк.

В файле нет имён файлов и путей. Содержимое разложено по именованным разделам, которые Мика знает. Восстановление никогда не создаёт файл по имени из копии, поэтому выйти за папку данных через копию нельзя.

Данные базы идут строками, а не готовым файлом `mika.db`. Причины:
- чужой файл SQLite мог бы нести триггеры, которые добавят правила «разрешать всегда» уже после предпросмотра;
- Мика сама решает, какие таблицы и столбцы принять, и проверяет каждую строку;
- базу не нужно подменять на ходу: строки пишутся в открытую базу одной транзакцией;
- версия схемы перестаёт быть помехой: берутся столбцы, которые есть и в копии, и в базе.

## Шифрование

С паролем шифруется всё тело, а не только ключи: переписка и заметки тоже личные.

- Ключ шифрования получается из пароля функцией PBKDF2-HMAC-SHA256: 600 000 повторов, случайная соль 16 байт. Число повторов записано в заголовке, поэтому его можно поднять без смены формата. При чтении принимается от 100 000 до 5 000 000: меньше — незнакомый файл, больше — попытка подвесить Мику.
- Из результата через HKDF-SHA256 получаются два ключа: ключ шифрования и ключ проверки пароля.
- Шифр AES-256-GCM. Тело режется на куски по 1 МБ, у каждого своя метка подлинности. Номер куска и признак последнего входят в одноразовое число, а хеш заголовка — в подписанные данные. Перестановка кусков, обрезка файла и правка заголовка обнаруживаются.
- Проверочное значение в заголовке даёт ясный ответ на неверный пароль: «Пароль не подошёл». Если пароль верный, а кусок не сходится — «Файл копии повреждён или изменён».
- Пароль: не короче 10 знаков и не длиннее 256. Проверка состава не делается, подсказка советует фразу. Пароль вводится дважды.
- Пароль нигде не хранится. Между предпросмотром и восстановлением в памяти процесса лежит только полученный из него ключ, не дольше 15 минут.
- Ключи провайдеров пишутся сразу в шифрующий поток. Временный файл при сохранении — это уже шифртекст.

Почему PBKDF2, а не Argon2. Argon2 лучше держит перебор на видеокартах, но его нет среди скачанных крейтов, а сборки в рабочих деревьях идут без сети. Крейт `ring` 0.17 уже собирается в проект как часть TLS (`reqwest` → `rustls`) и даёт всё нужное: PBKDF2, HKDF, HMAC, AES-256-GCM и случайные числа. Новых крейтов в `Cargo.lock` не появляется: `ring`, `flate2` и `base64` там уже есть, они добавляются в зависимости `mika-core`. BCrypt из Windows дал бы то же самое, но это небезопасный код в платформенном крейте, который нельзя проверить тестами ядра. Минимум в 10 знаков отчасти закрывает слабость PBKDF2. Имя функции записано в заголовке: формат 2 сможет перейти на Argon2id.

## Сохранение

Страница «Общие», блок «Перенос на другой ПК».

1. Выключатель «Зашифровать паролем и положить ключи», по умолчанию включён. С ним нужны пароль и его повтор.
2. Если выключить, страница пишет: «Без пароля файл не зашифрован и ключей в нём нет. Переписку, заметки и настройки прочитает любой, у кого окажется файл. Ключи на новом ПК придётся ввести заново».
3. Кнопка открывает окно Windows «Сохранить как». Место выбирает пользователь.
4. После сохранения показаны путь, размер, зашифрована ли копия и сколько в ней ключей, кнопка «Показать в папке».

Файл пишется во временное имя рядом и переименовывается в конце. При ошибке временный файл удаляется.

## Восстановление

1. Пользователь выбирает файл в окне Windows «Открыть». Мика читает заголовок и показывает дату, компьютер, версию, размер, зашифрован ли файл.
2. Для зашифрованной копии Мика спрашивает пароль.
3. Мика читает файл целиком, ничего не меняя, и показывает предпросмотр.
4. Пользователь отмечает, что восстановить, и нажимает «Восстановить», затем подтверждает ещё раз.
5. Мика сохраняет прежние данные, восстанавливает отмеченное и показывает итог с кнопкой «Перезапустить».

### Предпросмотр

Разделы с числами «в копии» и «сейчас на этом ПК»:

| Раздел | По умолчанию |
|---|---|
| Настройки и персонаж | отмечен |
| Переписка и архив | отмечен |
| Память: факты | отмечен |
| Заметки, дела, напоминания, свои команды | отмечены |
| Сценарии по событию | отмечены; восстанавливаются выключенными |
| Задачи по расписанию | **не отмечены** |
| Запреты | отмечены; добавляются к запретам этого ПК |
| Разрешения «всегда» | **не отмечены** |
| Ключи | отмечены, если копия зашифрована |

Отмеченный раздел заменяет то, что есть на этом ПК. Слияния нет: у него нет однозначного правила, а замена понятна. Исключение одно — запреты: запреты этого ПК восстановление не удаляет никогда, запреты из копии к ним добавляются. Иначе копия с одним посторонним запретом сняла бы запреты, которыми пользователь вырезал опасное из широкого разрешения. Раздел, которого в копии нет, отметить нельзя: так пустая копия не сотрёт заметки.

Два раздела сами начинают действовать без вопроса, поэтому не отмечены и восстанавливаются только тем, что показано на экране:
- **Разрешения «всегда».** Показаны первые 200 правил. Правила после двухсотого не восстанавливаются, и страница говорит, сколько их.
- **Задачи по расписанию.** Это напоминания вида «задача»: когда приходит время, их текст уходит модели как сообщение пользователя, и это платный запрос. Показаны первые 50 с текстом, временем и повтором; остальные не восстанавливаются. Просроченная задача сработает сразу после восстановления, страница об этом предупреждает. Обычные напоминания только показывают текст и восстанавливаются вместе с остальным.

Предпросмотр и восстановление проходят одни и те же строки в одном порядке, поэтому в базу попадает ровно то, что было в списке.

### Сценарии по событию

Сначала сценарии в копию не входили: сценарий сам запускает действия. Пользователь решил, что они должны переноситься, как остальное. Они вошли отдельным разделом, и перенос устроен так, чтобы файл не мог заставить Мику что-то делать саму.

- **Показаны по одному.** В предпросмотре у каждого сценария строка: имя, событие, программа или устройство, действие (поручение целиком или имя своей команды), пауза и предел в день. Показаны первые 30 — столько, сколько Мика вообще хранит; остальные не восстанавливаются.
- **Восстанавливаются выключенными.** Раздел отмечен по умолчанию именно поэтому: после восстановления ни один сценарий не сработает, пока пользователь не включит его на странице «Расширения». Итог перечисляет сценарии в списке «Будет выключено».
- **Без счётчиков.** Время последнего запуска, счёт дня и таблица запусков в файл не пишутся и из файла не читаются: столбцы выключателя и счётчиков из файла игнорируются. Пауза и счёт дня берутся из запусков, которые помнит этот ПК для того же имени (решение 0031: пределы нельзя обнулить).
- **Пределы эпика 19 проверяются при чтении.** Известное событие, имя, уточнение, поручение до 300 знаков одной строкой, пауза и предел в своих границах, отметка текста у сценария своей команды. Строка, которая не проходит, пропускается и считается среди негодных; исправлять её Мика не пытается, иначе в базу попало бы не то, что было в файле. Второй сценарий с тем же именем пропускается.
- **Своя команда должна быть на месте.** Сценарий, который запускает свою команду, восстанавливается, только если после восстановления команда с этим именем есть в базе: её принёс раздел «Свои команды» этой же копии или она уже была на ПК. Проверка идёт в конце чтения файла, по базе, когда команды уже записаны или оставлены. Сценарии без команды не пишутся, и итог называет их число. Предпросмотр помечает такие сценарии при текущих отметках.
- **Подтверждённый текст команды остаётся подтверждённым.** Отметка текста команды (16 цифр SHA-256) переносится со сценарием. Если команда на этом ПК говорит другое, сценарий не запустится и выключится с объяснением, как после любой правки команды.
- **Текст своей команды виден там, где сценарий включают.** Отметка из файла говорит только, что текст подтверждали на другом ПК; сам текст приходит из того же файла, а предпросмотр называет лишь имя команды. Поэтому страница «Расширения» показывает под сценарием своей команды её нынешний текст целиком, и описание раздела в предпросмотре просит прочесть его перед включением. Сценарий приходит выключенным, так что до включения текст успевают увидеть.
- **Замена, а не слияние.** Раздел заменяет сценарии этого ПК. Если из копии записать нечего (все строки негодные или все без команды), сценарии этого ПК остаются.
- **Слежения не переносятся.** «Подожди и скажи» живёт в памяти и на диск не пишется.

Блок «Проверь перед восстановлением» показывает то, чем чужой файл мог бы навредить:
- **Разрешения «всегда».** Каждое правило, которое будет восстановлено, списком: инструмент и шаблон. С ними Мика делала бы перечисленное без вопроса, поэтому они восстанавливаются только по отдельной отметке.
- **Задачи по расписанию.** Каждая задача, которая будет восстановлена: текст, время, повтор.
- **Адреса провайдеров.** Если адрес в копии отличается от нынешнего, а ключ для него остаётся с этого ПК, страница предупреждает: ключ будет уходить по новому адресу. Считается тот ключ, который на самом деле уйдёт: у речи, картинок и эмбеддингов свой ключ идёт раньше ключа модели. Если на этом ПК есть свой ключ речи, а копия его не заменяет, предупреждение показано, даже когда копия несёт ключ модели.
- **Серверы MCP**: имя и команда запуска или адрес. Если на этом ПК есть токен сервера с таким именем, а адрес в копии другой, страница предупреждает: после включения сервера токен будет уходить по адресу из копии.
- **Telegram**: идентификатор владельца. Если на этом ПК есть токен бота, а владелец в копии другой, страница предупреждает: после включения моста бот будет слушаться владельца из копии.
- **Ключи**: названия без значений и пометка «заменит ключ на этом ПК».

### Что восстанавливается выключенным

Всё, что слушает, смотрит, следит, запускает программы или принимает команды со стороны, после восстановления выключено:

- микрофон и просмотр экрана (правило проекта: они выключены, пока пользователь явно их не включил, а на этом ПК он их ещё не включал);
- чтение уведомлений, время в программах, история буфера обмена;
- мост Telegram: два ПК не должны опрашивать одного бота, а чужой файл не должен назначить владельца и включить мост;
- каждый сервер MCP: команда из файла не запускается, пока пользователь её не увидел и не включил сам;
- папки документов: список очищается, а итог перечисляет, какие папки были. Иначе Мика начала бы читать их и отправлять текст провайдеру эмбеддингов без действия пользователя на этом ПК;
- диктовка в любое окно (слушает микрофон) и вопрос про экран (снимает окно и отправляет картинку провайдеру): у каждого свой выключатель сверх микрофона и просмотра экрана, и оба приходят выключенными (решение 0030);
- голосовые сообщения моста Telegram, входящие и ответы голосом: включив мост заново, пользователь не должен вместе с ним включить платное распознавание и синтез (решение 0029);
- каждый сценарий по событию, см. выше.

То, что само ходит в сеть или само тратит деньги, копия включить не может. Оно остаётся включённым, только если включено и в копии, и на этом ПК:
- интернет-инструменты (правило проекта: они выключены, пока пользователь их не включил);
- календарь: Мика сама ходит по ссылке ICS, а ссылку копия может заменить;
- утренняя сводка и вечерний итог дня: платный запрос без просьбы (решение 0028);
- общий выключатель сценариев по событию: если на этом ПК сценарии поставлены на паузу, копия их не запускает.

Обратное правило у паузы расходов (решение 0028): если на этом ПК включено «На 100% не начинать платную работу самой», копия эту паузу не выключает. Выключатель — не вся пауза: её сняли бы и выключенный учёт, и лимит 0 или выше здешнего, и другая валюта, и заниженные свои цены. Поэтому пока на этом ПК бюджет действует (учёт включён, пауза включена, задан лимит дня или месяца), раздел расходов из копии не берётся совсем: учёт, лимиты, валюта и свои цены остаются как здесь. Если бюджет здесь не действует, лимиты и свои цены — обычные настройки и переносятся.

Группа инструментов, выключенная на этом ПК, остаётся выключенной, даже если в копии она включена.

Предпросмотр и итог перечисляют, что именно было включено в копии и стало выключено. Выключение действует сразу, не дожидаясь перезапуска.

Что остаётся от этого ПК, даже если настройки восстановлены:
- вид окна (островок или обычное окно), монитор, место и размер окна. Вид окна тоже: страница рисует то окно, которое открыто сейчас, и смена вида посреди восстановления убрала бы итог с экрана;
- путь к FFmpeg. По этому пути Мика запускает программу, поэтому путь из файла не берётся никогда: чужая копия назвала бы папку с чужим `ffmpeg.exe`, а сетевой путь ещё и выдал бы имя входа в Windows;
- папка отчётов глубокого поиска: это место на этой машине, куда Мика пишет файлы; путь из чужой копии назвал бы чужую сетевую папку;
- адрес файла обновлений и «проверять при запуске»: адрес из чужого файла подсунул бы чужой установщик;
- автозапуск.

Остальные настройки, привязанные к машине, переносятся, но запуск не ломают: пропавший микрофон и голос Windows заменяются теми, что по умолчанию. Экран первого запуска после восстановления настроек не показывается.

### Порядок записи

1. Прежние данные сохраняются тем же кодом, что и обычная копия, без пароля и без ключей: `%APPDATA%\Mika\backups\before-restore.mikabackup`. Файл один, новая копия заменяет старую только после удачного восстановления. Если сохранить не удалось, восстановление не начинается.
2. Текущий ход Мики останавливается.
3. База: одна транзакция. Таблицы отмеченных разделов очищаются и заполняются из копии; запреты только добавляются. Любая ошибка откатывает всё.
4. Ключи пишутся в Credential Manager. Ключ, который не записался, называется в итоге; данные при этом остаются восстановленными.
5. Настройки сохраняются в `config.toml` и заменяют настройки в памяти.

Перезапуск нужен, если восстановлены настройки, переписка или ключи: история разговора и часть настроек читаются при запуске. Кнопка «Перезапустить» запускает Мику заново после выхода, тем же приёмом, что установка обновления.

На экране первого запуска есть ссылка «У меня есть копия с другого ПК». Она открывает тот же блок восстановления.

## Инструменты

Инструментов нет, и это решение. Сохранение и восстановление работают с ключами, поэтому запускаются только рукой пользователя на страницах настроек и первого запуска.

- В реестр инструментов ничего не добавляется. Модель, команда из Telegram и сервер MCP вызвать сохранение или восстановление не могут: вызывать нечего.
- Путь к файлу не приходит из интерфейса. Его даёт окно Windows «Сохранить как» или «Открыть», которое открывает сама программа. Даже если бы текст модели попал в страницу как код, без руки пользователя в этом окне ничего не сохранится и не откроется.
- Инструменты управления окнами не видят окон самой Мики, это уже так: они отбирают окна только чужих программ.
- Правило «каждый инструмент проходит политику рисков» не затронуто: новых инструментов нет. Правило «высокий риск нельзя разрешить навсегда» держится и для восстановленных правил: проверка стоит в шлюзе при каждом вызове, а правило «всегда» с `*` внутри шаблона при восстановлении отбрасывается, как при создании.

## Правила безопасности

- **Ключи только под паролем.** Без пароля строки с ключами не пишутся. При чтении ключи принимаются только из зашифрованной копии.
- **Ключей нет в журнале и ошибках.** Тип секрета не печатается и не сериализуется. Ошибки копии — перечисление без данных пользователя; к тексту добавляется только ответ системы о файле или базе.
- **Имена ключей — по списку.** Из копии пишутся только записи с известными именами. Токен MCP пишется, только если сервер с таким именем есть в настройках после восстановления. Значение длиннее 1024 знаков отбрасывается.
- **Незнакомый формат.** Не те первые байты — «это не файл копии». Номер формата больше известного — отказ с просьбой обновить Мику. Незнакомые параметры шифрования — отказ. Незнакомые таблицы и виды строк внутри известного формата пропускаются, их число показано.
- **Пределы размера.** Файл до 1 ГБ, заголовок до 64 КБ, распакованное тело до 2 ГБ, строка до 16 МБ, до 5 миллионов строк, настройки до 1 МБ, до 64 ключей. Превышение — отказ до любых изменений.
- **Проверка строк.** Тип каждого значения сверяется со столбцом базы. Сообщение должно разбираться как сообщение чата, факт и своя команда — укладываться в свои пределы длины, правило — быть запретом или разрешением. Негодная строка пропускается и считается.
- **Системных сообщений в переписке нет.** Мика их в базу не пишет. Сообщение с ролью «система» из копии говорило бы с моделью голосом самой программы, поэтому такая строка отбрасывается. Принимаются роли пользователя, помощницы и инструмента.
- **Номера и время в разумных пределах.** Номер записи — от 1 до 2^53: больший заставил бы SQLite выдавать следующие номера случайно. Время напоминания — от 0 до начала 2100 года: планировщик складывает времена, дикое значение дало бы переполнение и срабатывание каждую секунду. Текст напоминания — до 2000 знаков. Закрытые напоминания из копии не берутся: они нигде не показываются.
- **Ничто не начинает действовать само.** Разрешения «всегда» и задачи по расписанию — только по своей отметке и только те, что показаны в списке. Сценарии по событию — только показанные и только выключенными. Настройки, которые включают датчик, сеть, платное действие без просьбы или запуск программы, из копии не включаются. Путь к программе и папка для своих файлов из копии не берутся.
- **Правила.** Запрет из копии заменяет разрешение на этом ПК. Разрешение из копии запрет на этом ПК не заменяет. Запрет этого ПК восстановление не удаляет.
- **Разрешение «всегда» действует только на ту цель, для которой дано.** Запрет — шаблон, `*` в нём значит «что угодно». Разрешение сравнивается с целью вызова целиком: правило `*` покрывает только вызовы, у которых сама цель и есть `*`, то есть инструменты без своей цели. На этом ПК иначе и не бывает: правило с `*` внутри цели создать нельзя. Но копия могла принести правило `av_folder — *` или `trigger_create — *`, и раньше оно разрешило бы без вопроса платное распознавание целой папки или создание сценария, для которых постоянного правила на всё нарочно нет (решения 0032 и 0031). Проверка стоит в политике (`RuleStore::find`), а не в чтении копии: откуда бы такое правило ни пришло, лишнего оно не разрешит.
- **Имена таблиц и столбцов в запросах — свои.** Имя из файла только сравнивается со списком, в текст запроса оно не попадает.
- **Предпросмотр ничего не меняет.** Базу он спрашивает один раз, до чтения файла (столбцы и числа), и не держит её, пока читает: большой файл не останавливает напоминания и чат.
- **Восстанавливается тот файл, который был показан.** Предпросмотр считает SHA-256 всего файла. Восстановление считает его заново и сравнивает; размер, время изменения и хеш заголовка сверяются тоже. Пока файл читается, он открыт без права записи для других программ: его нельзя изменить, удалить или подменить между проверкой и чтением. Изменился — нужно выбрать заново. Это закрывает и копию без пароля, тело которой больше ничем не защищено.
- **Ключ от копии не живёт дольше 15 минут.** Если восстановление отказано без изменений (не удалось сохранить прежние данные), файл остаётся выбранным только до конца тех же 15 минут.
- **Запись в журнал решений.** Сохранение и восстановление записываются как действия пользователя: что сделано и имя файла.

## Цена

- Сохранение и восстановление работают на этом компьютере и ничего не стоят.
- Проверка пароля — это 600 000 повторов хеша: на обычной машине около секунды, на слабой не замерено.
- Векторы памяти в копию не входят. После переноса Мика считает их заново при первом поиске по смыслу: это платные запросы к модели эмбеддингов, по её цене. Уходит тот же текст, что уходил на старом ПК. Об этом сказано в описании блока «Перенос на другой ПК».
- Указатель документов строится заново, когда пользователь снова добавит папки.

## Не сделано

- Слияние с данными этого ПК: только замена по разделам.
- Копия по расписанию, копия в облако, копия по просьбе в чате или из Telegram.
- Выбор разделов при сохранении и копия без переписки.
- Argon2id: нужен новый крейт.
- Затирание памяти процесса после работы с паролем и ключами.
- Включение задачи по расписанию по одной: отмечается весь раздел, показанный списком. То же у сценариев: раздел приходит целиком, включаются они по одному уже на странице «Расширения».
- Слияние сценариев копии со сценариями этого ПК: только замена.
- Показ текста своей команды рядом со сценарием в предпросмотре: показано имя команды. Текст виден после восстановления на странице «Расширения», под самим сценарием и в списке своих команд.
- Перенос бюджета на ПК, где свой бюджет уже действует: остаётся здешний, даже если в копии лимит строже. Строже его делает пользователь на странице «Расходы».
- Перенос пути к FFmpeg и вида окна: они остаются от этого ПК.
- Перенос профиля браузера Мики, журнала решений, времени в программах, векторов и указателя документов.
- Перенос моделей аватара: их папки ещё нет. Когда появится, это будет новый раздел формата.
- Сохранение и восстановление из терминального клиента.
- Подсказка модели «копия делается в настройках»: системная подсказка не растёт.

## Не проверено

- Окно выбора файла поверх островка: островок всегда сверху, окно Windows открывается как принадлежащее ему. На машине разработки это проверяется руками.
- Перенос между двумя настоящими ПК с разными именами пользователей.
- Запись и чтение всех видов ключей в настоящем Credential Manager, в том числе длинной ссылки календаря.
- Время PBKDF2 на слабой машине и восстановление большой переписки.
- Перезапуск после восстановления на установленной версии, в том числе пока сохраняется запись экрана: ожидание конца процесса проверено тестом на постороннем процессе, не на самом приложении.
- Блокировка файла копии на время чтения на сетевой папке и в папке облачного диска: проверено тестом только на локальном диске.
- Вид списка задач по расписанию и новых предупреждений в настоящем окне: проверены типами и тестами чистых функций.

## Что изменилось после проверки кода

Проверка нашла места, где чужой или подменённый файл получал больше, чем показано на экране. Правило теперь одно: **из файла приходит только то, что пользователь видел, и ничто из файла не начинает действовать само.** Исправлено:

- путь к FFmpeg и вид окна остаются от этого ПК;
- после слияния с эпиками 16–23: диктовка, вопрос про экран и голосовые Telegram приходят выключенными; вечерний итог и общий выключатель сценариев копия не включает; паузу расходов копия не выключает; папка отчётов глубокого поиска остаётся от этого ПК; сценарии по событию вошли в копию своим разделом и приходят выключенными;
- задачи по расписанию вынесены в отдельный раздел без отметки по умолчанию, со списком;
- разрешения «всегда» и задачи сверх показанных в списке не восстанавливаются;
- интернет-инструменты, календарь и утренняя сводка копией не включаются; выключенные здесь группы инструментов остаются выключенными;
- запреты этого ПК не удаляются;
- предупреждение об адресе считает ключ, который на самом деле уйдёт; появились предупреждения о токене MCP и владельце Telegram;
- системные сообщения, огромные номера записей и дикое время напоминаний отбрасываются;
- файл сверяется по SHA-256 целиком и заблокирован на время чтения;
- предпросмотр не держит базу;
- ключ от копии не переживает свои 15 минут после отказа.

Проверка слитого дерева (эпики 16–23 вместе) добавила:

- копия не снимает бюджет, который действует на этом ПК: раздел расходов тогда остаётся здешним целиком, а не только выключатель паузы;
- разрешение «всегда» из копии с шаблоном `*` не действует на инструменты, которые называют свою цель;
- текст своей команды показан под сценарием на странице «Расширения», где сценарий включают;
- кнопка «Перезапустить» ждёт конца прежнего процесса, а не две секунды: пока сохранялась запись экрана, приложение после восстановления не возвращалось (решение 0032).

## Что это меняет в дизайне

- §4 «Кто что решил»: копия хранит ключи только под паролем.
- §5 «Хранение»: папка `backups` и раздел «Копия и перенос».
- §8 «Политика рисков»: копия не инструмент; восстановленные разрешения «всегда» включаются отдельно; разрешение «всегда» покрывает только свою цель.
- §10 «Интерфейс»: ссылка на экране первого запуска и блок на странице «Общие».
